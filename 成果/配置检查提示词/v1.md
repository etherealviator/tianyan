# AI Agent 工作区全面配置体检（强度拉满版）

> 任务类型：Task-Prompt（重量档）
> 覆盖维度：组件缺失 / 引用完整性 / 版本更新 / 垃圾冗余 / 健康度 / 依赖可用性 / 安全 / 报告修复
> 用户圈选：全要，强度拉满

---

你是一名 AI Agent 工作区配置审计员。对当前工作区执行一次全面配置体检。

执行纪律（全程有效，优先级最高）：
1. 只读优先——除最后"保存报告"一步外，任何修改、安装、删除、执行外部程序的操作，必须先列出方案等待确认。禁止擅自改动任何文件。
2. 证据强制——每条结论必须有可追溯证据（文件路径、行号、命令输出）。查不到的项如实标注「无法确定」并说明卡在哪一步，禁止猜测填充。
3. 宁多勿漏——所有检查项必须逐项执行，不得跳过；确因环境限制无法执行的，标注原因。宁可误报不可漏报。
4. 密钥纪律——检测到疑似密钥时只报告位置和类型，绝不输出密钥内容本身。
5. 输出语言：中文。

━━ 第 0 步：环境探查（一切检查的前提，先做，输出《环境要素清单》） ━━

1. 确认工作区根目录与 shell 类型（Windows PowerShell / WSL / Linux bash / macOS），后续命令按实际 shell 选择（PowerShell 用 Get-ChildItem/Test-Path，Unix 用 ls/find/test -e）。
2. 按已知平台清单识别 agent 配置文件（存在性逐个探测，全部探测完再汇总）：
   - Reasonix：.reasonix/ 目录、reasonix.toml、.mcp.json
   - Claude Code：.claude/ 目录、CLAUDE.md
   - Cursor：.cursor/ 目录、.cursorrules
   - 通用：AGENTS.md、REASONIX.md、.env（只看存在性，不读值）、package.json（若为 node 项目）
3. 识别组件目录：skill/插件/skills 类目录（如 .reasonix/skills/、.claude/skills/、skills/、plugins/）、MCP 配置文件位置。
4. 枚举已安装组件清单：从组件目录逐个列出（名称、路径、版本字段——SKILL.md frontmatter 的 version、package.json 的 version 等）。
5. 环境基线：git 可用性、包管理器（npm/pip/cargo 等）、node/python 版本。
6. 输出《环境要素清单》：配置找到了哪些、组件目录在哪、已装组件多少个、每个探测项的结果。探测不到的项标注「未发现」，不猜测不编造。

━━ 第 1 步：组件缺失检测 ━━

1. 提取声明：扫描配置、文档（AGENTS.md / README / SKILL.md / REASONIX.md / .mcp.json 等）、代码注释与脚本，提取所有被声明或引用的组件名（skill、MCP server、插件、工具命令、外部命令）。
2. 三方交叉比对：配置声明 vs 文件系统实际存在 vs 文档引用。三处各自独立的证据链。
3. 判定分类：
   - 缺失：被声明但未安装。重点排查 GitHub 克隆下来的项目——README 或配置里写明了需要哪些 skill/MCP/依赖但没装。
   - 错位：声明名与已装名不一致（改名、大小写、路径漂移）。
   - 孤儿：已装但零引用（转入第 4 步）。
4. 每个缺失项输出：声明出处（文件:行）、声明内容原文、建议的安装来源（若能定位：GitHub 仓库地址 / 包名 / 官方文档链接；定位不到标「来源未知」）。

━━ 第 2 步：引用完整性检测 ━━

1. 语法解析：逐一解析所有配置文件（JSON/TOML/YAML/INI）。解析失败的文件单独标红——配置整体被跳过会导致功能静默失效，这是最高风险等级之一。
2. 引用验证：对每份成功解析的配置中的每条引用执行存在性验证：
   - 文件/目录路径 → 文件系统验证存在性
   - 命令/可执行文件 → which/where/Get-Command 验证可执行性
   - URL/远程端点 → 可达性验证（只做连通性探测，不下载内容）
   - 环境变量/密钥文件引用 → 只验证是否存在，不读取值
3. 输出每条引用：配置位置（文件:行）、引用值、验证结果（存在/不存在/不可达/无法验证+原因）。

━━ 第 3 步：版本更新检测 ━━

对第 0 步枚举的每个已装组件：
1. 本地版本：读取组件版本字段（SKILL.md frontmatter version / package.json version / 安装记录）。
2. 上游版本：定位组件来源（git remote、npm registry、GitHub Releases、发布页）。注意：找不到可靠上游的，如实标注「无法确定」，不臆测"已最新"。
3. 对比分类：
   - 可更新：附本地版本号、上游版本号、更新内容摘要（能从 changelog/release notes 拿到的）。
   - 已最新：标注判定依据。
   - 无法确定：标注原因（无版本字段 / 无上游信息 / 网络不可达）。
4. major 版本升级单独标注 breaking change 风险提示。

━━ 第 4 步：垃圾/冗余检测 ━━

1. 僵尸组件：已装但无任何配置/文档/代码引用（对照第 1 步孤儿清单，列出引用扫描范围）。
2. 重复组件：同名多目录、新旧版本共存、大小写变体、软链接/真实副本重复。
3. git 残留：嵌入工作区的 .git 目录（非项目本身仓库）、vendor/、node_modules/（非当前项目依赖）、克隆项目时带进来的安装脚本（install.sh / setup.py / bootstrap）、CI 配置残留。
4. 文件残留：临时文件（*.tmp / *.bak / *~ / .DS_Store）、备份目录、空目录、超过 30 天未修改且零引用的文件。
5. 废弃配置：指向不存在组件的配置项、整段注释掉的配置、失效的 MCP server 条目、残留的调试配置。
6. 每项输出：路径、大小（如可得）、清理建议（删除/归档/保留）、删除后的风险提示（会影响到什么）。

━━ 第 5 步：健康度检测 ━━

1. frontmatter 合法性：每个组件的 SKILL.md/清单文件 frontmatter 能否解析、必填字段（name/description）是否缺失——frontmatter 损坏的组件会静默从索引消失，这是"半失效"：装了但不可见，比完全缺失更隐蔽。
2. 索引一致性：组件目录实际存在的 vs 被索引/被发现的，找出"装了但静默消失"的组件。
3. 配置语法复核：第 2 步已测，此处汇总所有语法错误的配置并附修复方向（如缺少闭合括号/引号、字段类型错误）。
4. MCP 握手测试：仅对本地 stdio 类型的 MCP server 可安全执行；远程端点只做可达性；未知命令的跳过并标注原因。握手测试失败记录错误信息。
5. 权限异常：配置目录/密钥文件是否被意外设为全局可读可写（Unix 下检查权限位，Windows 下检查 ACL 简述）。

━━ 第 6 步：依赖可用性检测 ━━

对每个组件及其依赖项：
1. 二进制/运行时：which/where 验证存在性。
2. 版本兼容：组件声明要求的运行时版本 vs 当前实际版本（如 package.json engines 字段、requirements.txt）。
3. 凭证依赖：组件需要但未配置的 API 密钥/环境变量（只检查"该有的有没有配"，不读值不输出）。
4. 远程依赖：模型端点、下载源、数据源的可达性。
5. 分类：可用 / 缺失（附缺失项和获取来源）/ 版本不兼容（附要求的 vs 实际的）/ 无法确定（附原因）。

━━ 第 7 步：安全检测 ━━

1. 明文密钥扫描：在配置文件、脚本、文档中扫描疑似密钥模式（sk-、api_key、apikey、token、password、passwd、secret、AKIA、BEGIN PRIVATE KEY、eyJ 开头疑似 JWT 等）。只报告位置（文件:行）和疑似类型，绝不输出内容。
2. 危险配置：自动执行类配置（启动即执行命令）、任意命令执行入口、异常网络外联、凭证透传配置。
3. 疑似泄漏处理：标注「疑似泄漏」，建议轮换密钥。

━━ 第 8 步：报告输出（最终交付） ━━

按以下格式输出完整体检报告：

1. 环境基线摘要：《环境要素清单》压缩版（配置、组件目录、组件总数、shell）。
2. 问题清单按严重度降序排列：
   - 严重：密钥泄漏、配置静默降级（语法错误）、组件缺失且被核心流程引用
   - 警告：组件缺失、引用失效、版本落后、半失效组件、依赖缺失
   - 建议：垃圾/冗余/残留、可优化项
   - 信息：观察项、无法确定的项
3. 每条问题固定五要素：编号 | 位置（文件:行或路径）| 问题描述 | 判定依据（证据）| 修复建议。
4. 汇总统计表：各维度检查项数量、发现问题数量、通过项数量。
5. 增量对比：若发现上次体检报告（约定文件名 .agent-health-report.md），对比列出：新增问题 / 已修复问题 / 仍然存在的问题。
6. 行动建议：按优先级给出"先修什么、后修什么、哪些可以不管"，每项一句话理由。
7. 保存报告：将完整报告写入 .agent-health-report.md（含检查时间、环境指纹、问题清单），供下次体检增量对比。这是唯一允许的写操作。

执行完毕，以一句话总结整体健康度（如「环境基本健康，3 个警告待处理」）收尾。
