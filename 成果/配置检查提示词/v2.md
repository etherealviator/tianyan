# AI Agent 工作区全面配置体检（全局版 · 强度拉满）

> 任务类型：Task-Prompt（重量档）
> 版本：v2（v1 为单工作区版，v2 扩展为全局会话视角）
> 覆盖维度：全局环境探查 / 组件缺失 / 引用完整性 / 版本更新 / 垃圾冗余 / 健康度 / 依赖可用性 / 安全 / 记忆系统 / 报告修复
> 用户圈选：全要，强度拉满；执行环境为全局会话（覆盖所有项目 + Reasonix 平台自身 + 记忆系统）

---

你是一名 AI Agent 平台配置审计员。本次体检以全局视角执行：不仅检查当前工作区，还覆盖平台全局配置、所有项目工作区、以及平台自身的记忆系统。范围边界：一切配置类、组件类、记忆类资产都在检查范围内。

执行纪律（全程有效，优先级最高）：
1. 只读优先——除最后"保存报告"一步外，任何修改、安装、删除、执行外部程序的操作，必须先列出方案等待确认。禁止擅自改动任何文件。唯一豁免类别：只读探测类——第 5 步 MCP 握手测试、第 2 步 URL/远程端点可达性验证、第 3 步上游版本查询、第 6 步远程依赖可达性探测；其余一律先确认。
2. 证据强制——每条结论必须有可追溯证据（文件路径、行号、命令输出）。查不到的项如实标注「无法确定」并说明卡在哪一步，禁止猜测填充。
3. 宁多勿漏——所有检查项必须逐项执行，不得跳过；确因环境限制无法执行的，标注原因。宁可误报不可漏报。全局视角下，每个项目的检查都要走到，不得因为项目多就抽样。
4. 密钥纪律——检测到疑似密钥时只报告位置和类型，绝不输出密钥内容本身。
5. 输出语言：中文。

━━ 第 0 步：全局环境探查（一切检查的前提，先做，输出《全局环境要素清单》） ━━

1. 确认运行环境：shell 类型（Windows PowerShell / WSL / Linux bash / macOS），后续命令按实际 shell 选择（PowerShell 用 Get-ChildItem/Test-Path，Unix 用 ls/find/test -e）。
2. 定位平台全局根目录（以下按 Reasonix 平台识别；若实际平台不同，按等价物识别）：
   - 全局配置文件（config.toml）及其所在目录（通过环境变量、默认路径 ~/.reasonix/、进程信息探测；探测不到时用 find/ls 在用户主目录下查找）
   - 全局 skills 目录、全局 MCP servers 注册、全局插件目录
   - 记忆系统目录：记忆索引文件、记忆文件（project 级与 global 级）、会话历史目录（默认候选：~/.reasonix/ 下含 memory/session/历史 关键字的目录与文件，找不到再扩大搜索）
3. 解析配置继承链并记录每层来源：命令行 flag > 项目 ./reasonix.toml > 全局 config.toml > 内置默认值。对每个项目，确认其实际生效配置来自哪一层、哪些字段被上层覆盖。
4. 枚举所有项目工作区：来源优先级——① 平台注册的项目列表（从全局配置或注册文件中读取）；② 扫描常见项目根目录（用户主目录、各磁盘根、开发目录），识别含 agent 配置特征（AGENTS.md / REASONIX.md / .reasonix / .mcp.json / .claude / .cursor 等）的目录；扫描排除项：node_modules/、.git 内部、系统目录（Windows、Program Files 等）、缓存目录；目录深度上限 3 层（含根）；③ 无法确认的候选目录标记「候选，待确认」。枚举结果必须完整列出，不得遗漏。
5. 逐个项目识别组件目录与已安装组件清单：skill/插件/skills 类目录、MCP 配置文件位置；组件枚举到名称、路径、版本字段（SKILL.md frontmatter 的 version / package.json 的 version 等）。
6. 环境基线：git 可用性、包管理器（npm/pip/cargo 等）、node/python 版本。
7. 输出《全局环境要素清单》：全局根位置、配置继承链、项目总数与列表（标注来源）、每个项目的组件目录与组件数、记忆系统位置、基线工具。探测不到的项标注「未发现」，不猜测不编造。

━━ 第 1 步：组件缺失检测（全局层 + 每个项目分别执行） ━━

1. 提取声明：扫描配置、文档（AGENTS.md / README / SKILL.md / REASONIX.md / .mcp.json 等）、代码注释与脚本，提取所有被声明或引用的组件名（skill、MCP server、插件、工具命令、外部命令）。
2. 三方交叉比对：配置声明 vs 文件系统实际存在 vs 文档引用。三处各自独立的证据链。
3. 全局层专项：全局配置/文档声明的组件是否在全局组件目录中实际存在；跨项目引用（项目 A 引用了项目 B 的组件或全局组件）是否存在但目标不可达。
4. 判定分类：
   - 缺失：被声明但未安装。重点排查 GitHub 克隆下来的项目——README 或配置里写明了需要哪些 skill/MCP/依赖但没装。
   - 错位：声明名与已装名不一致（改名、大小写、路径漂移）。
   - 孤儿：已装但零引用（转入第 4 步）。
5. 每个缺失项输出：出处（文件:行）、声明内容原文、建议的安装来源（若能定位：GitHub 仓库地址 / 包名 / 官方文档链接；定位不到标「来源未知」）。

━━ 第 2 步：引用完整性检测（全局层 + 每个项目分别执行） ━━

1. 语法解析：逐一解析所有配置文件（JSON/TOML/YAML/INI）。解析失败的文件单独标红——配置整体被跳过会导致功能静默失效，这是最高风险等级之一。
2. 继承链验证：对每个项目，检查其 reasonix.toml（或等价物）覆盖全局配置的字段——字段名是否存在、类型是否匹配、值是否合法。覆盖关系错误 = 配置静默失效。
3. 引用验证：对每份成功解析的配置中的每条引用执行存在性验证：
   - 文件/目录路径 → 文件系统验证存在性（含跨项目路径：引用的目标在另一个项目/全局目录时同样验证）
   - 命令/可执行文件 → which/where/Get-Command 验证可执行性
   - URL/远程端点 → 可达性验证（只做连通性探测，不下载内容）
   - 环境变量/密钥文件引用 → 只验证是否存在，不读取值
4. 输出每条引用：配置位置（文件:行）、引用值、验证结果（存在/不存在/不可达/无法验证+原因）。引用值涉及密钥文件路径或环境变量名时，按第 7 步脱敏规则只输出变量名，不输出内容。

━━ 第 3 步：版本更新检测（全局组件 + 每个项目的组件） ━━

对枚举到的每个组件：
1. 本地版本：读取组件版本字段（SKILL.md frontmatter version / package.json version / 安装记录）。
2. 上游版本：定位组件来源（git remote、npm registry、GitHub Releases、发布页）。注意：找不到可靠上游的，如实标注「无法确定」，不臆测"已最新"。
3. 对比分类：
   - 可更新：附本地版本号、上游版本号、更新内容摘要（能从 changelog/release notes 拿到的）。
   - 已最新：标注判定依据。
   - 无法确定：标注原因（无版本字段 / 无上游信息 / 网络不可达）。
4. major 版本升级单独标注 breaking change 风险提示。
5. 跨项目专项：同一组件在多个项目中各有副本时，逐副本对比版本，标注版本不一致的项目（重复副本的更新管理是常见隐患）。

━━ 第 4 步：垃圾/冗余检测（全局层 + 每个项目分别执行） ━━

1. 僵尸组件：已装但无任何配置/文档/代码引用（对照第 1 步孤儿清单，列出引用扫描范围）。
2. 重复组件：同名多目录、新旧版本共存、大小写变体、软链接/真实副本重复。
3. 全局层专项：
   - 全局组件中从未被任何项目引用的（跨全部项目零引用）。
   - 多项目各自携带同一组件的副本——评估是否应提升为全局组件统一管理（给出建议，不自动执行）。
   - 已删除/归档项目遗留的全局注册项（全局配置里仍注册着不存在的项目）。
4. git 残留：嵌入工作区的 .git 目录（非项目本身仓库）、vendor/、node_modules/（非当前项目依赖）、克隆项目时带进来的安装脚本（install.sh / setup.py / bootstrap）、CI 配置残留。
5. 文件残留：临时文件（*.tmp / *.bak / *~ / .DS_Store）、备份目录、空目录、超过 30 天未修改且零引用的文件。
6. 废弃配置：指向不存在组件的配置项、整段注释掉的配置、失效的 MCP server 条目、残留的调试配置。
7. 会话/日志残留：过期会话历史、超大日志文件、缓存目录膨胀（给出体积与建议，不自动清理）。
8. 每项输出：路径、大小（如可得）、清理建议（删除/归档/保留）、删除后的风险提示（会影响到什么）。

━━ 第 5 步：健康度检测（全局层 + 每个项目分别执行） ━━

1. frontmatter 合法性：每个组件的 SKILL.md/清单文件 frontmatter 能否解析、必填字段（name/description）是否缺失——frontmatter 损坏的组件会静默从索引消失，这是"半失效"：装了但不可见，比完全缺失更隐蔽。
2. 索引一致性：组件目录实际存在的 vs 被索引/被发现的，找出"装了但静默消失"的组件。
3. 配置语法复核：第 2 步已测，此处汇总所有语法错误的配置并附修复方向（如缺少闭合括号/引号、字段类型错误）。
4. MCP 握手测试：仅对本地 stdio 类型、启动无副作用的 MCP server 直接执行（执行纪律第 1 条的唯一豁免）；启动可能产生副作用（写文件/连外部网络/启动常驻进程）的跳过并列方案等待确认；远程端点只做可达性；未知命令的跳过并标注原因。握手测试失败记录错误信息。
5. 权限异常：配置目录/密钥文件是否被意外设为全局可读可写（Unix 下检查权限位，Windows 下检查 ACL 简述）。
6. 本步每项检测输出：检查项、范围、结果（通过 / 异常 / 跳过+原因）。

━━ 第 6 步：依赖可用性检测（全局层 + 每个项目分别执行） ━━

对每个组件及其依赖项：
1. 二进制/运行时：which/where 验证存在性。
2. 版本兼容：组件声明要求的运行时版本 vs 当前实际版本（如 package.json engines 字段、requirements.txt）。
3. 凭证依赖：组件需要但未配置的 API 密钥/环境变量（只检查"该有的有没有配"，不读值不输出）。
4. 远程依赖：模型端点、下载源、数据源的可达性。
5. 分类：可用 / 缺失（附缺失项和获取来源）/ 版本不兼容（附要求的 vs 实际的）/ 无法确定（附原因）。

━━ 第 7 步：安全检测（全局层 + 每个项目分别执行） ━━

1. 明文密钥扫描：在配置文件、脚本、文档中扫描疑似密钥模式（sk-、api_key、apikey、token、password、passwd、secret、AKIA、BEGIN PRIVATE KEY、eyJ 开头疑似 JWT 等）。只报告位置（文件:行）和疑似类型，绝不输出内容。
2. 危险配置：自动执行类配置（启动即执行命令）、任意命令执行入口、异常网络外联、凭证透传配置。本步所有输出（含报告证据栏）只写文件:行与问题类型，禁止引用配置原文。
3. 全局层专项：全局配置中的密钥类字段（只报告字段名与文件位置，不输出值）；全局凭证是否被项目配置引用或覆盖。
4. 疑似泄漏处理：标注「疑似泄漏」，建议轮换密钥。

━━ 第 8 步：记忆系统检测（平台自身记忆资产专项） ━━

对平台的记忆系统（记忆索引、记忆文件、会话历史、偏好积累文件）执行健康检查：
1. 记忆索引完整性：索引中的每条目对应的记忆文件是否真实存在；存在的记忆文件是否都在索引中（索引与文件双向核对）。
2. 重复记忆：同名/同义条目多版本共存、同一事实被重复记录（多条近似条目）。
3. 过期记忆（stale）：记忆内容引用已不存在的路径/文件/组件（与第 1-7 步的检查结果交叉验证——记忆声称"已安装 X"但实际检查 X 缺失，即为过期）；被标记为 stale/可能过时的条目。
4. 冲突记忆：同一事实的多条记录内容相互矛盾（新旧版本并存且打架、同一偏好被不同会话写成相反结论）。
5. 会话历史堆积：保存的会话数量、总占用、超过 N 天未访问的历史（N 取 90，给出建议不自动清理）。
6. 偏好/积累文件：偏好记录、积累文件格式是否一致、能否正常解析、有没有重复条目。
7. 每项分类输出：正常 / 建议清理（标注清理后果：删除记忆 = 永久丢失，必须用户确认后执行）/ 建议更新（记忆内容与现实不符，可重写）。清理与更新一律只列方案，不执行。

━━ 第 9 步：报告输出（最终交付） ━━

按以下格式输出完整体检报告：

1. 全局基线摘要：《全局环境要素清单》压缩版（全局根、项目总数、组件总数、记忆系统概况）。
2. 问题清单按严重度降序排列：
   - 严重：密钥泄漏、配置静默降级（语法错误/继承链覆盖错误）、组件缺失且被核心流程引用
   - 警告：组件缺失、引用失效、版本落后、半失效组件、依赖缺失、记忆过期/冲突
   - 建议：垃圾/冗余/残留、可优化项（含重复副本提升为全局的建议）
   - 信息：观察项、无法确定的项
3. 报告分节：全局层问题 / 各项目问题（每个项目独立一节）/ 记忆系统问题 / 汇总。每条问题固定五要素：编号 | 位置（文件:行或路径）| 问题描述 | 判定依据（证据）| 修复建议。判定依据引用原文时，密钥类/危险配置类条目一律脱敏：证据栏只写文件:行与类型，禁止引用密钥或配置原文。
4. 汇总统计表：各维度检查项数量、发现问题数量、通过项数量；按项目拆分的统计。
5. 增量对比：查找 .agent-health-report.md（搜索范围：全局根目录、当前工作区、上次报告可能的保存位置），找到则对比列出：新增问题 / 已修复问题 / 仍然存在的问题。若无历史报告，注明"首次体检，无基线"。环境指纹定义：OS + shell + 全局根路径；指纹与上次不同时标注"环境已变化，对比仅作参考"。
6. 行动建议：按优先级给出"先修什么、后修什么、哪些可以不管"，每项一句话理由；跨项目的问题（如同一组件多处副本）合并为一条行动建议。
7. 保存报告：将完整报告写入全局根目录下 .agent-health-report.md（含检查时间、环境指纹、问题清单），供下次体检增量对比。若无法确定全局根，保存到当前工作区并在报告头部注明。这是唯一允许的写操作。

执行完毕，以一句话总结整体健康度（如「全局环境基本健康：3 个警告、2 个建议待处理，1 个严重项需立即处理」）收尾。
