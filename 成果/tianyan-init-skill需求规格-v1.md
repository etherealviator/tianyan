# tianyan-init Skill 需求规格 v1

> 定位：给新会话编写 tianyan-init skill 的完整任务指令。照此执行，产出可复现天衍运行模式的初始化 skill。
> 生成日期：2026-08-05

---

## 一、任务定义

编写一个名为 `tianyan-init` 的 Skill（项目级，.reasonix/skills/ 下），作用：在任何一台机器/平台上，通过一次交互完成天衍运行环境的探测、搭建（或复用）、适配与装载，使目标环境具备完整复现当前天衍模式的能力。

**复现单元 = 一个 skill（tianyan-init）+ 一个 xml（tianyan-prompt.xml）+ 一个可选存储后端。**

## 二、背景与设计约束（为什么这么设计）

1. 天衍当前是"提示词 + Reasonix 平台 + Obsidian vault"三位一体。复现的障碍是平台绑定：obsidian MCP、task/fleet 子代理、search MCP 都是 Reasonix 专属能力，换平台即失效。
2. 因此必须按"平台相关性"切分：**xml 只留平台无关部分（人格 + 锻造协议 + 行为律），skill 承载平台适配（探测、创建、映射、装载）**。
3. skill 保持薄：主体逻辑在 skill 正文，细节（模板内容、映射表、适配文档）放 vault/本地文件按需读取，不把天衍全套审计+履历逻辑塞进 skill body 烧 token。
4. 天衍 v0.25 已有 environment_profile 能力探测 + fallback 降级机制，本 skill 是把它从"Reasonix 专属"泛化成"平台无关抽象"的落地者。

## 三、职责边界

**必须做：**
- 环境能力探测（文件系统 / Obsidian / git 远程 / 子代理 / 搜索）
- 存储后端推荐与用户选择
- vault 目录脚手架创建（含模板文件）
- 已有 vault 的检测、复用与迁移（禁止无脑新建覆盖）
- 共享/隐私分级询问
- xml 装载 + 平台映射表写入

**严禁做：**
- 修改 xml 中的人格层、锻造协议层、行为律（那是 xml 自己的事）
- 把天衍全套框架逻辑内联进 skill body
- 无确认就覆盖已有 vault 数据
- 把 token/密码等凭据写入 vault 或 skill 文件

## 四、执行流程（skill 运行时的步骤序列）

```
1. 探测
   ├─ fs：目标目录可写？（默认 D:\tianyan 或当前工作区）
   ├─ obsidian：Obsidian MCP 可用？目标 vault 路径存在？
   ├─ git：git 可用？~/.local/bin/gh 或 credential helper 已配置？remote 已接？
   ├─ 子代理：task/fleet 类工具是否暴露
   └─ 搜索：search MCP 是否可用
   → 产出：能力画像（每项有/无/降级）

2. 推荐（探测驱动，不给用户裸选）
   ├─ obsidian 可用且 vault 存在 → 推荐 Obsidian（默认）
   ├─ 仅 fs → 推荐本地文件系统
   └─ 用户提到多设备/多实例 → 推荐 git 远程
   → 用户确认或推翻（用户推翻时按用户选择）

3. 创建或复用
   ├─ 目标路径无 vault → 创建五目录脚手架 + 模板文件
   ├─ 目标路径有 vault → 检查版本兼容，询问复用/重建
   └─ 复用 → 校验结构完整性，缺的目录/模板补建，不删已有数据

4. 隐私分级（仅当用户选择 git 远程/共享时触发）
   ├─ 询问共享范围：全库 / 仅框架资产（tianyan/、AGENTS.md、领域模板）
   └─ 写入共享配置，后续写入按配置路由

5. 装载与适配
   ├─ 将 tianyan-prompt.xml 放入平台约定的提示词位置
   ├─ 生成平台映射表（见第六节）
   └─ 输出完成报告：能力画像 + 装载位置 + 缺失能力清单
```

## 五、目录脚手架规格（创建时必建）

```
成果/            # 交付产物迭代（子目录按成果名）
反馈/            # 偏好/纠错/奖赏/修改意见（子目录按成果名）
  └─ 天衍/       # 天衍自身偏好档案
领域/            # 类型模板 + 维度积累（跨成果共享）
tianyan/         # 天衍框架自身文档
流程证据/        # 锻造履历归档
  └─ _目录规范.md # 履历文件命名与结构规范
inbox/           # 观察记暂存（git 忽略，不提交）
```

**模板文件（参照现有 vault 的 领域/ 目录格式）：**
- 领域/类型-{name}.md（任务类型维度锚点）与 类型-{name}-积累.md（触发计数）各一份示例
- 领域/审计-{Type}.md（审计维度模板，Type = Agent/Skill/SystemPrompt/TaskPrompt/EvalRubric）
- 流程证据/_目录规范.md
- 反馈/天衍/偏好.md（空模板，含信号类型说明）
- 根目录 .gitignore（墨猫书架/、inbox/ 忽略；.reasonix/attachments/ 白名单放行 tianyan-prompt.xml 与 backup/）

模板内容从当前 vault 的对应文件复制为基准（若 skill 运行环境中已有参考 vault 则读其文件，否则内置精简版）。

## 六、平台适配层（能力抽象映射）

skill 生成/维护一份平台映射表（存 vault tianyan/ 或本地配置），把平台无关能力名映射到具体平台的工具：

| 抽象能力 | Reasonix 映射 | 降级路径 |
|---------|--------------|---------|
| 知识存储 | mcp__obsidian__ | fs 直读（本地目录） |
| 联网搜索 | mcp__search__ | AI 联想兜底并显式标注 |
| 子代理 | task / fleet / parallel_tasks | 主实例自审 |
| 文件直写 | write_file / edit_file | —（最低保证） |

天衍 xml 内部引用一律用抽象能力名；skill 负责在装载时把映射表喂给运行环境。

## 七、交互原则

- 高吞吐优先：探测结果一次性展示，用户圈选/推翻，不逐项追问
- 推荐优先于提问：先给推荐（含理由一句话），用户只需确认或推翻
- 复用优先于新建：探测到已有数据先问复用
- 敏感操作（覆盖、删除、共享公开）必须显式确认

## 八、验收标准（写完后自测清单）

1. 空环境跑一遍：五目录 + 模板 + .gitignore 全部创建，xml 装载成功，能力画像输出
2. 已有 vault 环境跑一遍：检测到复用提示，不覆盖现有数据，缺失部分补建
3. 无 obsidian 环境跑一遍：降级为本地 fs，无报错，完成报告标注"obsidian 不可用"
4. 无 git/gh 环境跑一遍：跳过 git 相关步骤，不阻塞
5. 完整跑通后：换台机器复制 成果/ + tianyan-prompt.xml，跑 skill 即恢复当前工作模式
6. skill body 不得内联天衍九层锻造/审计/履历全量逻辑（以读文件代替内联）

## 九、交付物清单

- .reasonix/skills/tianyan-init/SKILL.md（或对应 skill 文件）
- 内置模板文件（精简版，供无参考 vault 时使用）
- 本规格文档作为 README 附注

## 十、不做的事（本期明确排除）

- 不写公共数据库/MCP server 服务端（git 远程已满足当前共享需求）
- 不改 tianyan-prompt.xml 本体（xml 适配是独立迭代任务）
- 不处理云端同步的冲突合并策略（git 天然处理）
- 不做多用户贡献协议（远期，非本期）
