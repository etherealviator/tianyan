# 去AI味润色审计 Skill — no-ai-flavor v2.0.0（转型版）

> 锻造日期：2026-08-04（v1 叙事版 → v2 转型版）
> 定位：中文非创作类文本（论述/分析/报告/公文/技术文档/邮件/说明/总结）的润色与审计。清除AI味 + 结构审计 + 信息密度铁律。
> 转型原因（实证）：叙事创作的执行端超出当前模型能力边界——v1 的灵魂审计六条能"识别"问题但"修正"时连续翻车（克制留白/编造细节/强行闲笔/代词密度，均被用户逐句批回）。识别能力模型有，创作执行没有。转型为非创作类文本——这是信息组织任务而非灵魂创作任务，模型能力可覆盖。
> 完整历史：v1 叙事版见 成果/去AI味叙事Skill/v1.md；转型决策记录见 领域/类型-去AI味-积累.md 维度9。

<skill_definition name="no-ai-flavor" version="2.1.0" pure_functional="true">
  <description>中文非创作类文本的润色与审计。适用：论述/分析/报告/公文/技术文档/邮件/说明/总结/会议纪要等。核心目标：清除AI味（套话连接词/空洞升华/排比堆砌/金句/注水）+ 结构审计 + 信息密度铁律。定位：作为所有非创作类写作产出的固定优化/审计模块被串行调用。目标：AI味完全清除；兜底：无法自然清除处如实标注（P4），不硬改。</description>

  <function_signature>
    <input>
      <field name="text" type="text" required="true">待处理文本（纯文本或文件内容。文件场景：调用方传入文件路径或文件内容，逐字读取，处理中不损失文件信息）</field>
      <field name="mode" type="enum" required="false" default="polish">polish（润色现有文本）/ audit（只审不改，输出审计报告）</field>
      <field name="genre" type="text" required="false">文本用途+压缩度目标（决定展开度）。报告-作业/汇报/学术：保留论证展开与段落完整，只清AI套话；报告-决策/内参：高密度骨架化；邮件：适中，保留语气与礼仪；公文：保留正式语体与必要格式语；技术文档：高密度。缺失时按"通用-中等压缩"处理（清AI味，保留论证展开）。</field>
      <field name="output_format" type="enum" required="false" default="text">text（纯文本）/ text_with_report（正文+审计报告）</field>
    </input>
    <output>
      <field name="result" type="text" required="true">处理后文本。text 模式只输出正文；text_with_report 模式输出正文+审计报告。</field>
      <field name="audit_report" type="object" required="false" present_when="mode=audit 或 output_format=text_with_report">
        <field name="fingerprint_hits" type="list">AI味指纹命中清单（条目+位置+处理动作）</field>
        <field name="structure_audit" type="object">结构审计五维逐条判定（通过/未通过+依据）</field>
        <field name="score" type="object">五维评分（各/10，总分/50）。评分锚点：直接性=直述信息vs绕圈铺垫；结构=骨架清晰vs段落功能不明；密度=信息饱满vs注水空话；准确=术语/数据可靠vs含糊其辞；精炼=无冗余vs大量废话。45-50优秀/35-44良好/&lt;35需重写。</field>
        <field name="changes_summary" type="text">改动摘要：改了什么、为什么</field>
      </field>
    </output>
  </function_signature>

  <core_principles>
    <principle id="P1" name="信息密度铁律">任何改动不得删减或模糊原文的事实、逻辑、数据、细节信息。宁可保留一段"不够漂亮"的话，不可删掉一个真实的信息点。删任何内容前必须确认：是否承载信息（事实/数据/逻辑环节/限定条件）。承载则保留，不承载才可删。</principle>
    <principle id="P2" name="原意铁律">改写必须忠实于原意，尤其数据、结论、因果链。理解错原意而"润色得更顺"是比原文有AI味更严重的错误。存疑时保留原文，不猜。</principle>
    <principle id="P3" name="直接性铁律">非创作类文本以传达信息为唯一目的。直接、具体、不绕。删一切不承载信息的装饰（铺垫、寒暄、虚词、升华）。但：直接≠压缩。论证展开、背景交代、目的陈述是文体要素（承载信息），不是注水——压缩度由 genre 决定，不得把有信息量的展开压成提纲。区分两种"废话"：无信息的话（删）vs 有信息但需要篇幅的话（保留）。</principle>
    <principle id="P4" name="诚实铁律">遇到无法自然处理的段落，如实标注"此处AI味无法自然去除，原因：XXX"，禁止用技巧性改写掩盖。优先级声明：AI味完全清除是目标，P4是兜底——两者冲突时，诚实优先于"看起来干净"。</principle>
  </core_principles>

  <execution_logic>
    <step id="1" name="类型识别">
      判断输入文本类型。非创作类（论述/分析/报告/公文/技术文档/邮件/说明/总结）→ 完整执行。叙事/创作类（小说/散文/随笔/续写）→ 降级为基础指纹清理（只执行 step 2 硬指纹扫描与 step 4b 修正），并在报告中标注"创作类文本的深度处理超出本skill能力边界"（见 领域/类型-去AI味-积累.md 维度9——创作执行端依赖模型能力，非skill可弥补）。
    </step>
    <step id="2" name="指纹扫描">
      对文本执行 AI 味指纹库扫描（见 ai_fingerprint_library，硬指纹全量）。扫描结果记录为 fingerprint_hits 清单，进入审计报告。
    </step>
    <step id="3" name="结构审计">
      对文本执行结构审计五维（见 structure_audit），逐条判定"通过/未通过+依据"。此步只判定，不改写。
    </step>
    <step id="4" name="修正执行">
      仅 polish 模式执行。audit 模式跳过本步（直接进入 step 6）。按以下顺序执行，顺序不可颠倒：
      <sub_step id="4a">信息核验：对照 P1/P2，确认每处拟改动不损失信息、不改原意。发现损失→放弃该处改动，标注保留原因。</sub_step>
      <sub_step id="4b">硬指纹清除：按指纹库逐层处理——词汇层替换/删除；句式层打破（三段式拆二拆四、否定式排比直述化、破折号揭示删除、系动词回避改"是"）；结构层打散（引言-三点-总结改其他骨架、结尾升华改具体结论）；修辞层删除空洞比喻与金句。</sub_step>
      <sub_step id="4c">结构修正：按结构审计判定逐条处置——骨架不清→重排段落功能；逻辑跳跃→补衔接或标注缺口；开头绕→直接给结论/数据/问题；结尾虚→改为具体结论或下一步动作；段落功能重叠→合并。压缩度校准：按 genre 决定展开度——报告-决策/技术文档：可压缩至骨架；报告-作业/学术：保留论证展开与完整段落，只清套话与注水，不压信息；邮件：保留语气；公文：保留正式语体。压缩不当（把有信息量的展开压成提纲）视为修正事故，回退重改。</sub_step>
      <sub_step id="4d">直接性校准：P3 执行——删铺垫、删寒暄、删虚词（"在一定程度上""从某种角度来说"类）、删不承载信息的修饰；术语不准确→标注待核实（不猜测替换）；长句拆短或短句合并，使节奏服务于信息密度。</sub_step>
    </step>
    <step id="5" name="复核">
      对修正后文本重新执行 step 2 指纹扫描与 step 3 结构审计，确认无遗漏、无新增。若修正引入新AI味（如"为了简洁而简洁"造成的断裂），修正痕迹。
    </step>
    <step id="6" name="输出">
      按 function_signature 输出。text 模式只输出正文。text_with_report 模式输出正文+完整审计报告（fingerprint_hits + structure_audit 五维判定 + 五维评分 + changes_summary）。audit 模式：result 回显原文（逐字保留），audit_report 输出完整审计结果。
    </step>
  </execution_logic>

  <ai_fingerprint_library>
    <hard name="词汇层">
      <item>套话连接词：值得注意的是 / 总而言之 / 综上所述 / 首先其次最后 / 此外 / 然而 / 不难发现 / 众所周知 / 显而易见 / 在当今社会 / 随着XX的发展 / 发挥着重要作用 / 具有重要意义 / 不可或缺 / 不言而喻 / 综上所述</item>
      <item>空洞升华词：彰显 / 凸显 / 折射出 / 诠释 / 谱写 / 画卷 / 篇章 / 里程碑 / 划时代 / 深刻意义 / 深远影响 / 不可磨灭 / 赋能 / 抓手 / 闭环（无实质内容时删）</item>
      <item>抽象空洞修饰：大幅度 / 显著 / 极大 / 全面 / 积极 / 深入 / 有力（无具体数据支撑时，用数字/事实替换或删除）</item>
      <item>虚词缓冲：在一定程度上 / 从某种角度来说 / 不得不承认 / 值得注意的是 / 需要指出的是 / 综上所述可见（删，直接陈述）</item>
    </hard>
    <hard name="句式层">
      <item>三段式排比：A、B、C 三项并列（拆为两项或四项，或打散）</item>
      <item>否定式排比：不是A而是B / 不仅仅A更是B / 不……而是……（直述化）</item>
      <item>虚假范围：从X到Y（X、Y不在有意义尺度上时，删除）</item>
      <item>破折号揭示：破折号后接"不是……是……"或金句（删破折号，直述）</item>
      <item>系动词回避：作为 / 标志着 / 充当 / 代表着（换"是"）</item>
      <item>同义词循环：同一句内换词重复同一事物（合并）</item>
      <item>代词高频重复：连续3句以上同一人称代词开头（修正三法：承前省略/物作主语/称呼替代）</item>
    </hard>
    <hard name="结构层">
      <item>引言-三点-总结骨架（打散：结论先行/问题切入/数据开头）</item>
      <item>结尾必升华：结尾为金句/意义拔高（改为具体结论/数据/下一步动作）</item>
      <item>开头复述题目或背景（删，直接进入内容）</item>
      <item>每段都"总结陈词"：段尾重复段首观点（删重复）</item>
    </hard>
    <hard name="修辞层">
      <item>空洞比喻：为比喻而比喻（删除，换成具体事实或数据）</item>
      <item>金句欲：听起来可引用的句子（重写为具体陈述）</item>
      <item>故作高深：抽象名词堆砌制造"深刻感"（"本质上是存在方式的重新定义"类，删或改为具体表述）</item>
    </hard>
  </ai_fingerprint_library>

  <genre_protection>
    <!-- 文体要素保护清单。以下要素是文体的组成部分，不是AI味，清指纹时不得删除（按 genre 匹配）。 -->
    <item genre="报告（学术/作业/汇报）">目的陈述段、论证展开（每条判断的理由与对比）、结论完整性、格式层级（一、（一）1.）。万金油开头（"随着……发展"）与空洞升华（"具有重要意义"）仍清除，但背景交代本身保留并改干净。</item>
    <item genre="公文">正式称谓、必要格式语（"现将……报告如下"）、文号/落款要素。清除的是机械套话，不是公文语体。</item>
    <item genre="邮件">称呼、目的句、礼仪收尾（去机器感但保留礼仪）。</item>
    <item genre="技术文档">术语、规格描述、上下文说明。压缩不等于删规格。</item>
    <item genre="通用">判断基准：要素承载信息或承担文体功能→保留；万金油填充→清除。</item>
  </genre_protection>

  <structure_audit>
    <!-- 非创作类文本的结构审计五维。 -->
    <item id="T1" name="骨架清晰度">全文有没有一个明确的组织原则（时间/因果/总分/问题-方案）？每段承担什么功能？读完全文能否一句话说清"这篇在讲什么"？说不清→骨架模糊。</item>
    <item id="T2" name="逻辑连贯性">段落之间有无跳跃？论证链条有无断裂（前提缺失/结论无据/因果颠倒）？衔接是"因为所以"的真实逻辑，还是"此外然而"的表面连接词？</item>
    <item id="T3" name="开头直接性">第一句是否直接给出结论/数据/问题？还是先铺垫背景/寒暄/复述题目？</item>
    <item id="T4" name="结尾实在性">结尾是具体结论/数据/下一步动作，还是升华/展望/口号？（"我们有信心…""必将…"类删）</item>
    <item id="T5" name="信息饱满度">每段是否有实质信息（事实/数据/判断）？删掉形容词后段落还剩什么？删完只剩空话→该段注水。</item>
  </structure_audit>

  <constraint_boundary>
    <never_sacrifice>信息密度 / 原意 / 数据与事实正确性 / 术语准确性（不确定的术语标注待核实，不猜测替换）</never_sacrifice>
    <may_adjust>句式 / 结构 / 节奏 / 词汇 / 修辞（在无损信息和原意的范围内）</may_adjust>
    <style_guardrail>去AI味 ≠ 加入人味表演。非创作类文本不需要"人味"——需要的是干净、直接、准确。禁止为"显得自然"加入口语、自嘲、情绪化表达。文体的正式度由 genre 决定：公文有公文的格式，邮件有邮件的语气，删AI味不等于删正式度。</style_guardrail>
  </constraint_boundary>

  <error_handling>
    <case>输入为空或不可识别 → 要求重新提供，不猜测。</case>
    <case>超长输入 → 分段处理，段间以主题连续性衔接。</case>
    <case>异常字符（乱码/异常标点） → 原样保留，不猜测，不"修复"。</case>
    <case>数据/术语存疑 → 标注"待核实"，不猜测替换（P2/P4）。</case>
    <case>叙事/创作类文本 → 降级为基础指纹清理，标注"创作类深度处理超出本skill能力边界"（见 领域/类型-去AI味-积累.md 维度9）。</case>
    <case>某段AI味无法自然去除 → 如实标注"此处保留AI味，原因：XXX"，禁止硬改掩盖（P4）。</case>
    <case>信息密度冲突（改写会损失信息） → 保留原文，标注"该处为保信息未改"（P1）。</case>
  </error_handling>

  <version>2.1.0</version>
</skill_definition>

## 转型说明

**v1 → v2 删了什么**：灵魂审计六条（叙事专用）、龙族模式、人物性格基准表、continue 模式、闲笔/赌注/幽默归属测试。

**v2 新增了什么**：结构审计五维（骨架/逻辑/开头/结尾/密度）、直接性铁律（P3）、genre 文体校准、创作类文本降级标注。

**为什么这版能成**：非创作类文本的"好"有客观标准——信息准确、逻辑连贯、表达直接。这些不需要创作天赋，只需要判断力和纪律。而判断力和纪律，正是模型有、且这场对话验证过的（识别层从没翻车，翻车的一直是生成层）。
