# tianyan-init

天衍运行环境的探测、搭建（或复用）、适配与装载。执行者为当前平台上的 AI——本文件不假设平台能力，探测结果驱动一切决策。

## 复现单元

天衍 = 人格 + 锻造协议 + 行为律（xml 内）+ 平台适配（本 skill）+ 知识存储（vault）。

本 skill 是复现单元的执行者：探测环境 → 选择/搭建存储后端 → 装载 xml → 生成平台映射 → 输出完成报告。一次交互后，目标环境具备完整复现天衍模式的能力。

## 运行前置

- 最低保证：目标目录文件系统可写。
- 平台缺能力时按「降级」处理，不报错不阻塞；降级项必须出现在完成报告的缺失清单中。
- 全流程铁律：复用优先于新建；推荐优先于提问；敏感操作（覆盖/删除/公开共享）必须显式确认；凭据不入库。
- 目标目录：默认当前工作区，用户可指定。
- 中途失败恢复：任一阶段失败时，已完成步骤保留，输出失败报告与断点位置，流程可安全重跑——各步骤幂等，重复运行走复用/补建路径，不产生重复、不覆盖已有数据。
- git 操作统一在隐私分级完成后执行——首次 push 前必须已确认共享范围并联动 .gitignore，禁止把未定级的目录推上远程。

## 执行流程

### 阶段 0：能力探测

按序执行七探针（平台、fs、obsidian、xml、git、子代理、搜索），每项产出三态：可用 / 不可用 / 降级，附探测证据（命令输出/文件存在性/平台能力清单或官方文档）。

| 探针 | 探测内容 | 可用判定 | 降级/分支路径 |
|---|---|---|---|
| 平台 | 当前平台名与能力清单（来源：平台能力清单/官方文档/工具调用列表） | 平台名可识别 | 未知平台 → 完成报告标注 |
| fs | 目标目录可写性 | 实际写入临时文件成功 | 不可写 → 人工接管 |
| obsidian | 平台 obsidian 集成 + vault 路径存在性 | 集成可调用且 vault 根存在 | 无集成 → 本地目录（分支 A）；集成可用但 vault 不存在 → 按分支 A 创建，建成后提示用户用 obsidian 打开目标根作为新 vault |
| xml | tianyan-prompt.xml 定位（常见位置：core/（仓库标准）、.reasonix/attachments/（旧运行时位置）、用户指定） | 找到 | 未找到 → 记录缺失并输出获取指引（从原机器 core/ 或 成果/ 复制），不阻塞后续 |
| git | git/gh CLI、credential helper、remote 配置 | git 命令可用 | git 可用无 remote → 本地版本控制；git 不可用 → 跳过 |
| 子代理 | 平台子代理/并行任务能力 | 平台能力清单声明或实测可用 | 主实例自审 |
| 搜索 | 平台联网搜索能力 | 平台能力清单声明或实测可用 | AI 联想兜底并显式标注 |

探测完成后一次性展示完整能力画像（七项 + 证据），不逐项追问。

### 阶段 1：存储后端推荐

推荐由探测结果驱动，每条带一句话理由；用户确认或推翻。

1. obsidian 可用且 vault 存在 → 推荐 Obsidian（默认）：天衍原生形态，图链接/双链/模板基准齐备。
2. 仅 fs 可用 → 推荐本地目录：零依赖最低保证。
3. 用户提及多设备/多实例 → 推荐 git 远程（可与 1 组合）：版本控制 + 多机同步，冲突合并 git 天然处理。
4. 用户推翻 → 按用户选择执行，但执行受探测事实约束——所选后端探测不可用时：先告知不可用及降级影响，用户仍坚持 → 按所选意图执行对应降级分支，并在完成报告标注「所选后端未经验证，按降级路径兜底」；选择不在推荐集时，先验证目标可写再继续。

### 阶段 2：创建或复用

按阶段 1 选定后端分三支，每支独立闭环：

**分支 A：无 vault 且本地创建**
触发：obsidian 不可用、无集成、集成可用但 vault 路径不存在，或用户选择本地；且目标目录无天衍结构、目录为空或仅含系统文件。
0. 前置检查：
   a. 天衍结构检查：目标目录是否已有天衍结构（领域/ 类型模板、流程证据/_目录规范.md 存在性）——已有则转入分支 B 复用逻辑，不重复创建。
   b. 目录内容检查：目录非空且含用户文件（非本流程产物）→ 转入分支 B 步骤 5 询问（库内补建天衍目录 / 新建独立目录），不静默写入。
1. 建五目录 + 反馈/天衍/ + inbox/ + .tianyan/（结构见「目录脚手架规格」）。
2. 复制 templates/ 全部文件到对应位置（落位映射见「模板资源」）；目标位置已有同名文件 → 询问是否覆盖（默认跳过保留既有，报告标注）。
3. 根目录 .gitignore：目标根已有 .gitignore → 询问合并方式（追加模板规则 / 保留既有仅补缺 / 覆盖）后执行；无 → 写入模板内置。
4. 若同时选了 git 远程：git 初始化与首推统一在阶段 3 完成（见阶段 3 步骤 4），本分支不提前执行 git 操作。

**分支 B：有 vault（复用优先）**
触发：obsidian 可用且 vault 存在，或用户指定已有目录。
1. 天衍结构特征检查：领域/ 类型模板存在？流程证据/_目录规范.md 存在？tianyan/ 框架文档存在？
2. 版本兼容检查：xml 已在阶段 0 定位 → 读取 xml 内 version_info，与 tianyan/ 框架版本文档对比，差异在完成报告中标注（仅提示，不阻断）；xml 未定位 → 跳过版本对比并在报告标注；tianyan/ 框架文档不存在 → 版本对比对象缺失，标注「框架版本未知」跳过对比。
3. 结构完整 → 直接复用，报告「复用」。
4. 结构缺失 → 询问：补建缺失部分（推荐，不删已有数据）/ 重建（备份到 目标根/../{vault名}-backup-{时间戳}/ 或用户指定位置，显式确认后执行；恢复方式=将备份复制回原位置）。
5. 目录存在但非天衍结构（普通知识库，或非空目录含用户文件）→ 询问：库内补建天衍目录（推荐）/ 新建独立目录（选定后，后续步骤的目标目录切换为新目录）。
6. 若同时选了 git 远程：git 配置与首推统一在阶段 3 完成（见阶段 3 步骤 4；复用场景已有 git 仓库则跳过 init，仅补 remote/push）。

**分支 C：目标不可写**
触发：fs 探测失败且无替代目录。
输出错误报告与人工接管指引，终止流程。

### 阶段 3：隐私分级与 git 初始化（仅 git 远程/共享时触发）

触发：阶段 1 选择 git 远程或任何共享后端。
1. 推荐共享范围：核心资产（core/ + 领域/ + scripts/ + tianyan/ 白名单 最小集）——复现必需的最小集；反馈/、流程证据/、.reasonix/、backup/ 含个人数据与内部资产，排除（本地保留）；用户可推翻为全库（成果/ 加入共享）。
2. 写入共享配置（有 vault → vault/tianyan/共享配置.md；仅 fs → 目标根/.tianyan/share-config.md）：范围 + 排除清单。
3. 按所选范围联动 .gitignore（.gitignore 不存在则先创建，已存在按分支 A 步骤 3 的合并策略处理）：核心资产 → 追加排除 成果/、反馈/、流程证据/；全库 → 保持模板默认。追加后校验隐私项（inbox/ 等）已覆盖，未覆盖则提示用户补充后继续。
4. git 初始化与首推（隐私分级完成前禁止 push）：git init（复用场景已有仓库则跳过）→ add → 初始 commit → remote add（已有 remote 则跳过）→ push（credential helper 可用则自动推；否则提示用户手动 push，不阻塞其余步骤）。首推前核对推送内容与共享范围一致。

### 阶段 4：装载与适配

1. **xml 装载**：xml 已在阶段 0 定位；放入平台约定的提示词位置——Reasonix：core/tianyan-prompt.xml（reasonix.toml 的 system_prompt_file 指向）；其他平台：按其 system prompt 配置位置；无约定位置：输出建议路径，用户确认后放置。未定位到 xml 时，输出缺失指引（从原机器 core/ 或 成果/ 复制）后继续其余步骤。
2. **映射表生成**：将探测结果写入平台映射表（有 vault → vault/tianyan/平台映射.md；仅 fs → 目标根/.tianyan/platform-map.md），格式见「平台映射表」。映射表把 xml 内部的抽象能力名绑定到本平台实际工具——xml 本体不修改。写入采用覆盖写（每次装载重新生成），重复运行幂等。
3. **完成报告**：能力画像 + xml 装载位置 + 映射表位置 + 缺失能力清单（每项附降级路径）+ 首启指引（如何验证装载成功：跑一遍映射表列出的核心能力；首先读 目标根/tianyan/ 框架文档与 流程证据/_目录规范.md——仅 fs 模式下框架文档位于 目标根/tianyan/；流程证据/ 为本地审计资产，不进共享范围）。

## 目录脚手架规格

```
<目标根>/
├── core/          提示词本体（tianyan-prompt.xml）+ skills/（与 xml 同仓）
├── 成果/          交付产物迭代
├── 反馈/          偏好/纠错/奖赏
│   ├── 天衍/      天衍自身偏好与已知缺陷
│   └── 审计日志/  外部交叉核验报告落位（可选，_目录规范.md 协议引用）
├── 领域/          类型模板 + 维度积累 + 审计模板
├── tianyan/       框架文档（有 vault 时承载 平台映射.md、共享配置.md）
├── 流程证据/      锻造履历（含 _目录规范.md）
├── scripts/       校验脚本（validate-prompt.js）
├── .tianyan/      本地配置（仅 fs 模式：share-config.md、platform-map.md；git 忽略）
├── inbox/         观察记（git 忽略）
└── .gitignore     模板内置（含 .tianyan/ 排除）
```

命名空间说明：有 vault → 配置写入 vault/tianyan/（随库版本控制）；仅 fs → 配置写入 目标根/.tianyan/（本地配置，git 忽略，不随共享推送）。

## 模板资源

templates/ 随本 skill 捆绑，模板与落位映射：

| 内置文件 | 落位目标 |
|---|---|
| 类型-示例.md | 领域/类型-{实际类型}.md（复制后按需改名扩充） |
| 类型-示例-积累.md | 领域/类型-{实际类型}-积累.md |
| 审计-{Agent/Skill/SystemPrompt/TaskPrompt/EvalRubric}.md | 领域/同名 |
| _目录规范.md | 流程证据/_目录规范.md |
| 偏好.md | 反馈/天衍/偏好.md |
| .gitignore | <目标根>/.gitignore |

复制策略：用户提供参考 vault（含完整模板的既有 vault，可跨机）→ 优先从参考 vault 复制对应文件（更完整）；否则用内置模板。内置为精简版，新 vault 可后续自行扩充。概念区分：参考 vault 是模板来源，目标 vault 是本次搭建/复用的落位——两者可以是同一 vault（复用场景），也可以是不同 vault（参考来源 + 新目标）。

注意：模板文件中的 {创建日期}、{类型名} 等占位符，复制落位时替换为实际值。

## 交互原则

1. 高吞吐优先：探测结果一次性展示，用户圈选/推翻，不逐项追问。
2. 推荐优先于提问：先给推荐（含一句话理由），用户只需确认或推翻。
3. 复用优先于新建。
4. 敏感操作（覆盖、删除、公开共享）必须显式确认。

## 禁忌

1. 修改 xml 中的人格层、锻造协议层、行为律。
2. 把天衍全套框架逻辑内联进本 skill 正文——以读文件代替内联。
3. 无确认覆盖已有 vault 数据或用户文件——非空目录、同名文件、既有 .gitignore 一律先询问。
4. token/密码等凭据写入 vault 或 skill 文件。
5. 静默跳过探测失败项——缺失能力必须出现在完成报告的缺失清单中。
6. 隐私分级完成前执行 git push——首次推送内容必须与已确认的共享范围一致。

## 验收自检（执行完成后逐条核对）

1. 空环境：五目录（成果/反馈/领域/tianyan/流程证据）+ 反馈/天衍/ + inbox/ + .tianyan/ + 模板 + .gitignore 全部创建，xml 装载成功，能力画像输出。
2. 已有 vault：检测到复用提示，不覆盖现有数据，缺失部分补建。
3. 无 obsidian：降级本地 fs，无报错，完成报告标注「obsidian 不可用」。
4. 无 git/gh：跳过 git 步骤，不阻塞。
5. 换机复现：复制 成果/ + core/tianyan-prompt.xml + core/skills/（skill 随平台技能目录迁移），跑本 skill 即恢复天衍**模式**（skill 定义 + 提示词 + 脚手架）；领域积累/反馈等**数据**恢复需同步对应 vault 目录——模式恢复与数据恢复显式区分。
6. 本 skill 正文未内联天衍九层锻造/审计/履历全量逻辑。
7. 重复运行：同一环境再跑一次，走复用/补建路径，不产生重复目录、不覆盖已有数据。
8. git 远程场景：首次 push 前隐私分级已完成、.gitignore 已联动共享范围，推送内容与范围一致。
9. 非空目录场景：目标目录含用户文件时走询问路径，不静默写入任何文件。
