# tianyan-init Skill — 需求规格 v1（README 附注）

> 本文件是 tianyan-init 的设计规格原文 + 交付说明。规格为准绳，SKILL.md 为执行体。
> 交付日期：2026-08-05

---

## 一、任务定义
编写一个名为 tianyan-init 的 Skill（项目级，core/skills/ 下），作用：在任何一台机器/平台上，通过一次交互完成天衍运行环境的探测、搭建（或复用）、适配与装载，使目标环境具备完整复现当前天衍模式的能力。

复现单元 = 一个 skill（tianyan-init）+ 一个 xml（tianyan-prompt.xml）+ 一个可选存储后端。

## 二、背景与设计约束
1. 天衍当前是"提示词 + Reasonix 平台 + Obsidian vault"三位一体。复现的障碍是平台绑定：obsidian MCP、task/fleet 子代理、search MCP 都是 Reasonix 专属能力，换平台即失效。
2. 因此必须按"平台相关性"切分：xml 只留平台无关部分（人格 + 锻造协议 + 行为律），skill 承载平台适配（探测、创建、映射、装载）。
3. skill 保持薄：主体逻辑在 skill 正文，细节（模板内容、映射表、适配文档）放 vault/本地文件按需读取，不把天衍全套审计+履历逻辑塞进 skill body 烧 token。
4. 天衍 v0.25 已有 environment_profile 能力探测 + fallback 降级机制，本 skill 是把它从"Reasonix 专属"泛化成"平台无关抽象"的落地者。

## 三、职责边界
必须做：环境能力探测（文件系统/Obsidian/git 远程/子代理/搜索）；存储后端推荐与用户选择；vault 目录脚手架创建（含模板文件）；已有 vault 的检测、复用与迁移（禁止无脑新建覆盖）；共享/隐私分级询问；xml 装载 + 平台映射表写入。

严禁做：修改 xml 中的人格层、锻造协议层、行为律；把天衍全套框架逻辑内联进 skill body；无确认就覆盖已有 vault 数据；把 token/密码等凭据写入 vault 或 skill 文件。

## 四、执行流程
1. 探测：fs（目标目录可写）→ obsidian（MCP 可用？vault 路径存在？）→ git（可用？gh/credential helper 配置？remote 已接？）→ 子代理 → 搜索。产出能力画像（每项有/无/降级）。
2. 推荐（探测驱动，不给用户裸选）：obsidian 可用且 vault 存在 → 推荐 Obsidian（默认）；仅 fs → 推荐本地；用户提到多设备/多实例 → 推荐 git 远程。用户确认或推翻。
3. 创建或复用：无 vault → 创建五目录脚手架 + 模板；有 vault → 检查版本兼容，询问复用/重建；复用 → 校验结构，缺的补建，不删已有数据。
4. 隐私分级（仅选 git 远程/共享时触发）：询问共享范围（全库/仅框架资产），写入共享配置。
5. 装载与适配：xml 放入平台约定的提示词位置；生成平台映射表；输出完成报告（能力画像 + 装载位置 + 缺失能力清单）。

## 五、目录脚手架规格（创建时必建）
core/（提示词本体 tianyan-prompt.xml + skills/，与 xml 同仓）；成果/（交付产物迭代）；反馈/（偏好/纠错/奖赏，子目录 天衍/）；领域/（类型模板 + 维度积累）；tianyan/（框架文档）；流程证据/（锻造履历，含 _目录规范.md）；scripts/（校验脚本）；inbox/（观察记，git 忽略）。

模板文件（参照现有 vault 领域/ 目录格式）：领域/类型-{name}.md 与 类型-{name}-积累.md 各一份示例；领域/审计-{Type}.md（Type = Agent/Skill/SystemPrompt/TaskPrompt/EvalRubric）；流程证据/_目录规范.md；反馈/天衍/偏好.md（空模板）；根目录 .gitignore（墨猫书架/、inbox/、.tianyan/、.reasonix/、反馈/、流程证据/ 忽略；core/ 与 tianyan/ 白名单随共享范围联动）。

模板内容从当前 vault 对应文件复制为基准（skill 运行环境已有参考 vault 则读其文件，否则内置精简版）。

## 六、平台适配层（能力抽象映射）
skill 生成/维护平台映射表（存 vault tianyan/ 或本地配置），把平台无关能力名映射到具体平台工具：

| 抽象能力 | Reasonix 映射 | 降级路径 |
|---------|--------------|---------|
| 知识存储 | mcp__obsidian__ | fs 直读（本地目录） |
| 联网搜索 | mcp__search__ | AI 联想兜底并显式标注 |
| 子代理 | task / fleet / parallel_tasks | 主实例自审 |
| 文件直写 | write_file / edit_file | —（最低保证） |

天衍 xml 内部引用一律用抽象能力名；skill 负责在装载时把映射表喂给运行环境。

## 七、交互原则
高吞吐优先：探测结果一次性展示，用户圈选/推翻，不逐项追问；推荐优先于提问：先给推荐（含理由一句话），用户只需确认或推翻；复用优先于新建；敏感操作（覆盖、删除、共享公开）必须显式确认。

## 八、验收标准
1. 空环境跑一遍：五目录 + 模板 + .gitignore 全部创建，xml 装载成功，能力画像输出
2. 已有 vault 环境跑一遍：检测到复用提示，不覆盖现有数据，缺失部分补建
3. 无 obsidian 环境跑一遍：降级为本地 fs，无报错，完成报告标注"obsidian 不可用"
4. 无 git/gh 环境跑一遍：跳过 git 相关步骤，不阻塞
5. 完整跑通后：换台机器复制 成果/ + tianyan-prompt.xml，跑 skill 即恢复当前工作模式
6. skill body 不得内联天衍九层锻造/审计/履历全量逻辑

## 九、交付物清单
core/skills/tianyan-init/SKILL.md；内置模板文件（精简版）；本规格文档作为 README 附注。

## 十、不做的事（本期明确排除）
不写公共数据库/MCP server 服务端（git 远程已满足当前共享需求）；不改 tianyan-prompt.xml 本体（xml 适配是独立迭代任务）；不处理云端同步冲突合并（git 天然处理）；不做多用户贡献协议（远期）。

设计决策备注：
- 审计模板与 _目录规范.md 为完整内置而非精简——它们是固化标准，精简即失真；"精简版"原则应用于类型/积累/偏好这类示例性文件。
- 版本兼容检查落为「结构特征检查 + tianyan/ 框架版本对比」，差异仅报告标注不阻断（规格四节 3 的细化）。
- 映射表文件路径：有 vault → vault/tianyan/平台映射.md；仅 fs → 本地 .tianyan/platform-map.md。
- 淬炼层（L7.6 子代理审计）吸收 10 条建议至 v1.1.0：xml 定位并入探测（S1）、分支 A 前置检查转复用（S2）、隐私分级联动 .gitignore 排除项（S3）、参考/目标 vault 概念区分（S4）、中途失败恢复规则（S5）、模板落位映射 + 可选 反馈/审计日志/（S6）、首启指引（E1）、证据来源具体化（E2）、push 策略（E3）、验收幂等条（E4）、隐私推荐优先（E5）、平台探针（E6）、措辞两处（W1/W2）。
- **v1.2.0 修订（2026-08-05，v0.26 先守轨补审驱动）**：天衍框架 v0.26 将淬炼还原为「先守后攻双轨」（整体质量终检 + 遗留重大问题复查），补跑子代理先守轨审计发现 2 个阻断级问题并修复：①B1 git 初始化与首推整体移入阶段 3「隐私分级完成后执行」——首次 push 前必须已确认共享范围并联动 .gitignore，禁止未定级目录上远程；②B2 非空目标目录防覆盖——分支 A 触发条件补「目录为空或仅含系统文件」，非空目录转分支 B 询问路径，.gitignore 合并与同名模板文件一律先询问。另吸收结构性 S2（.tianyan/ 本地配置命名空间入脚手架 + git 忽略）、S3（分支 B 补 git 配置）、增强 E1-E5、措辞 W1/W3。E6（审计模板增补 GS08 时序/隐私执行一致性维度）未改框架资产，进候选池待用户圈选。终检：11/11 落实、无遗留重大问题、结构性建议枯竭 → 收敛。
- 已知措辞级项：仅 fs 模式下 tianyan/ 为结构性空壳目录（空目录不推送，「核心资产」最小集实际由 core/+领域/ 构成）——不影响行为，随下次措辞修订处理。
