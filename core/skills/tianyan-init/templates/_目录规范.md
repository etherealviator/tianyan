# 流程证据目录规范

> 锻造履历归档。每条交付物对应一条履历记录，供独立审计实例交叉核验。

## 目录结构

```
流程证据/
├── _目录规范.md              ← 本文件
├── {YYYY-MM-DD}_{路由}_{名称简写}.md
└── ...
```

## 文件名格式

```
{YYYY-MM-DD}_{路由}_{名称简写}.md
```

- 日期为交付完成日期
- 路由取值：Agent-Definition / Skill-Definition / System-Prompt / Task-Prompt / Instant-Prompt / Schema-Definition / Eval-Rubric / Audit-Report / Knowledge-Artifact
- 名称简写：对应交付物名称，不超过 20 字

## 履历内容结构

```yaml
---
forge_date: {YYYY-MM-DD}
route: {路由}
mode: forge | express | unknown
deliverable: {成果路径}  # 关联的交付物路径
integrity: A | B | C      # 流程完整度自评
---
```

## 字段说明

| 字段 | 说明 |
|------|------|
| mode | forge=完整九层；express=省流模式；unknown=无法追溯 |
| integrity | A=九层+监天完整走完；B=核心层已走但部分跳过；C=省流模式 |
| 状态 | executed / skipped / express |
| 关键证据 | 具体可追溯的证据，不是泛化描述 |

## 外部交叉核验协议

外部独立实例（其他 AI、人工审查、工具分析）读取锻造履历时：

1. 扫描 流程证据/ 目录获取所有履历列表
2. 从履历中读取 route / mode / integrity 过滤感兴趣的目标
3. 对每条履历中的「逐层记录」与「关键证据细节」做合理性判断
4. 交叉核对：履历声称「executed」的层是否在交付物中有对应体现
5. 交叉核对：履历声称「skipped」的层是否有足够的原因说明
6. 交叉核对：监天审计结论（L7.5_监天）与交付物实际质量是否匹配
7. 产出审计报告写入 反馈/审计日志/ 或用户指定位置

独立实例与天衍不共享推理路径——交叉核验具有博弈价值的前提是推理独立。
