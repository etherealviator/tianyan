## Obsidian 故障诊断结论

**服务端健康，客户端会话失效。** 证据链：
- REST API HTTP 200（127.0.0.1:27123 / 27124）
- MCP 端点完整握手测试通过：initialize → 200 + mcp-session-id；notifications/initialized → 202；tools/list → 200 返回工具列表
- 认证正常：data.json apiKey 与全局 config.toml 一致（64位 hex），Bearer 头校验通过
- 端口监听正常：27123/27124 Listen，Obsidian 进程 3408 Responding=True

根因：Obsidian 于 2026-08-01 21:24 重启过（进程 StartTime 21:24:31）。MCP session 是内存态的——Obsidian 重启后所有旧 session 失效，客户端（Reasonix）持有的旧 session id 继续请求 → 404 "Session not found"。**非配置问题、非认证问题、非网络问题。**

修复：Reasonix 客户端需重新握手（重启 Reasonix 或新会话自动重新 initialize）。Obsidian 保持运行即可。若反复出现，考虑客户端侧是否缓存 session 且不自动重连——届时检查 Reasonix 的 MCP 重连逻辑。

补充：早期 curl 测试出现 401 是 bash 引号嵌套导致 KEY 变量为空（脚本问题），python 直接读 data.json 的 key 验证为 200，排除 key 错误可能。
