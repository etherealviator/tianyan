## 事故链

1. **泄漏**：仓库推送 GitHub 公开仓库（etherealviator/tianyan）时，历史提交中含敏感文件——`.obsidian/`（Obsidian 工作区+插件 data.json，明文含 **Local REST API Key** 与 **RSA 私钥**）、`reasonix.toml`、`.mcp.json`、`obsidian-local-cert.pem`、`tianyan/obsidian-mcp-手机接入配置.md`（含 API Key 明文+内网地址+0.0.0.0 监听说明）。违反 AGENTS.md 提交白名单（当时仅 墨猫书架/、inbox/ 在 .gitignore）。
2. **清理**：用户确认彻底清理历史。执行 `git filter-branch --index-filter 'git rm -r --cached ...'` 重写全部历史移除敏感文件，`gc --prune=now` 清对象，force push 覆盖远端。
3. **二次事故**：filter-branch 重写完成后 checkout 到新 HEAD——新 HEAD 不含这些文件，git 将工作区中"已跟踪但新 HEAD 不存在"的文件**从磁盘删除**。当时 .gitignore 尚未加入保护规则。**.obsidian/（整个目录）、reasonix.toml、.mcp.json、obsidian-local-cert.pem、两个手机接入配置文档 从本地磁盘消失。**

## 教训（已固化到 AGENTS.md 与 .gitignore）

1. **filter-branch 会删工作区文件**——重写历史后 checkout 新 HEAD，已跟踪但新 HEAD 不含的文件被移除。正确顺序：**先加 .gitignore 保护 → 再 filter-branch → gc → force push**。本次顺序反了（先删后保护）。
2. **任何 git add -A 前自查敏感文件**——AGENTS.md 已补「绝不上传」清单 + 每次 add 前 git status 自查。
3. **密钥泄漏必须立即轮换**——已公开的 API Key/私钥不可复用；Obsidian 重装时重新生成。
4. **push 公开仓库前检查历史**——不只是当前工作区，历史提交中的敏感文件同样暴露。
