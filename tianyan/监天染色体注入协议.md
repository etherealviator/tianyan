# 监天染色体注入协议

> 监天在交付前将审计维度以 `<audit>` 模块的形式注入天衍交付物，使交付物获得运行时自审能力。
> 注入目标：所有产出型路由的最终交付物（Agent-Definition / Skill-Definition / System-Prompt / Task-Prompt / Eval-Rubric / Schema-Definition）。
> 注入时机：锻造引擎 L7（注魂）完成后、L8（交付）之前。

---

## 注入流程

```
天衍锻造完成 L7（注魂）
  │
  ├─ 获取交付物文本 + 成果类型标签
  │
  ├─ 调用监天
  │   ├─ 输入：交付物文本 + 成果类型标签 + 本轮用户诉求清单
  │   └─ 输出：审计报告 + 注入模块
  │
  ├─ 审计等级裁决
  │   ├─ "不通过" → 阻断交付，退回锻模
  │   ├─ "带条件通过" → 标记问题，注入后放行
  │   └─ "通过" → 注入后放行
  │
  ├─ 注入 <audit> 模块到交付物
  │   └─ 根据成果类型选择对应的审计维度组
  │
  └─ 进入 L8（交付）
```

---

## 按成果类型的注入策略

### Agent-Definition（XML 结构）

在 `</agent_definition>` 闭合标签之前注入 `<audit>` 模块，作为 Agent 的自审子系统。

```xml
<agent_definition>
  <!-- ... 原有内容 ... -->
  <audit>
    <origin>监天 v2.0.0</origin>
    <injected_at>{时间戳}</injected_at>
    <trigger>每次核心动作（如执行工具调用、输出文本、状态变更）后自动触发</trigger>
    <dimensions>
      <item id="GA01" name="结构完整性" severity="阻断">
        <trigger>核心动作执行后</trigger>
        <check>identity 是否包含 name、self_conception、core_promise？</check>
        <fix>补全缺失字段</fix>
      </item>
      <!-- ... 根据成果类型映射的维度组 ... -->
    </dimensions>
    <fuse>
      <rule>连续两次自审发现阻断级问题 → 进入严格模式，阻断所有核心动作直到用户显式确认放行</rule>
    </fuse>
    <limitation>
      <item>监天不做运行时审计，仅做静态文本分析</item>
    </limitation>
  </audit>
</agent_definition>
```

### Skill-Definition（XML 结构）

在 `</skill_definition>` 闭合标签之前注入 `<audit>` 模块。

```xml
<skill_definition>
  <!-- ... 原有内容 ... -->
  <audit>
    <origin>监天 v2.0.0</origin>
    <injected_at>{时间戳}</injected_at>
    <trigger>每次被调用时触发</trigger>
    <dimensions>
      <item id="GS01" name="输入输出 schema" severity="阻断">
        <trigger>调用前</trigger>
        <check>输入字段类型/必填/缺省行为是否与定义一致？</check>
        <fix>校验不匹配时阻断调用并返回具体字段名</fix>
      </item>
      <!-- ... Skill 审计维度组 ... -->
    </dimensions>
    <limitation>
      <item>运行时输入校验依赖调用方传入的数据质量</item>
    </limitation>
  </audit>
</skill_definition>
```

### System-Prompt / Task-Prompt（纯文本）

在提示词末尾追加 `<audit>` 自审指令块，以纯文本形式嵌入。

```
--- 自审规则 ---
[GA01 结构完整性] 每次输出前检查：是否包含所有必要组成部分？
  缺失时：补全缺失模块
[GA04 逻辑闭环] 输出前检查：条件分支是否覆盖了所有已知场景？
  未覆盖时：标注未覆盖场景并说明原因
[GA07 AI味检测] 输出后检查：是否包含"当然""不过需要注意的是"等表达？
  检出时：替换为平视表达
--- 自审结束 ---
```

### Eval-Rubric（纯文本）

在评估标准末尾注入自审规则，让评估者可以自我检查评估的一致性。

```
--- 自审规则 ---
[GER01 可衡量性] 每条评分标准是否有通过/不通过的具体判别法？
  若否：标注该标准为"不可衡量"，建议补充
[GER03 一票否决] 被评估对象是否触发了一票否决条件？
  若是：直接判定为不通过，不继续评分
--- 自审结束 ---
```

## 运行时行为

| 自审结果 | 行为 | 用户感知 |
|---------|------|---------|
| 阻断级问题 | 阻断当前动作，输出修正方向 | 看到阻断消息和修正指引 |
| 警告级问题 | 记录日志或追加到输出末尾提示 | 输出中附带警告标注 |
| 建议级问题 | 仅内部记录 | 无感知 |
| 熔断触发（连续阻断） | 阻断所有核心动作，等待用户确认 | 看到熔断消息和"确认放行"提示 |

---

## 注入最小化原则

- 注入的 `<audit>` 模块不改变交付物的核心行为逻辑
- 注入的审计维度数量不超过该成果类型维度组的总数（不额外增加冗余维度）
- 用户可以通过在交付要求中声明 `no_audit: true` 来跳过注入
- 监天染色体层文档中的"落地检查项"跟踪注入协议是否被天衍框架实际执行
