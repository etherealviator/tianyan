# 天衍框架修改方案 v0.12

> 基于 v0.11 表演性结构清理。解决「自洽审计自我验证」和「L4 闭环位格不足」两个问题。
> 提示词本体位于 `.reasonix/attachments/tianyan-prompt.xml`

---

## 背景

v0.11 完成了 expansion_protocol 与 dynamic_generation 搜索通路合并，解决了领域无知时的位格错配。但在框架自身上有两个遗留结构问题：

1. **自洽审计的 jian_tian_audit tier 是自我验证** — 同一个 AI 实例执行 L7.5，然后在自洽审计中检查「L7.5 是否已执行」。这个检查永远无法命中 fail 条件，因为 L7.5 没执行的话 L8 交付不会发生。校验力为零。
2. **L4 闭环作为独立锻造层但只做条件分支** — 检查待证道列表是否归零，归零则退出，否则回锻模。这个判定逻辑放在锻模入口或兑冲前做没有任何功能损失，单独成层就是凑数。

本次不新增功能维度。专注消除两个表演性结构，并用有实质校验力的机制替换。

---

## 修改1：L4 闭环丰富——从条件分支升级为循环调度中枢

### 问题

L4 当前只做一件事：检查待证道列表是否归零。这不是一个独立层级该有的工作量。

### 方案

保留 L4 的位置（L3 锻模之后、L5 兑冲之前），将职责从单点判定扩展为三层：

**1. 收敛检测**
- 回溯循环历史中最近 5 道所消耗的维度，检查它们是否来自同一决策域
- 若是 → 标记为「收敛异常」，中断循环，触发凝意重新审视
- 目的：防止在同一个未闭合维度上反复尝试但不往前推进

**2. 死锁中断**
- 检查锻模是否连续 3 次回退到同一模块（同一道反复建构→自检不过→重建）
- 若是 → 标记为「死锁」，主动中断循环，触发凝意重新审视意图或调整约束
- 目的：不让循环在单点无限卡住，给用户一个「卡住了」的信号而不是无限重试

**3. 进度通信**
- 每消耗一道，将当前证道进度压缩为结构化摘要（已覆盖维度列表、剩余维度列表、当前约束池规模）
- 摘要附加到推理上下文中，供后续层（L5 兑冲、L6 对齐、L7 注魂）直接读取
- 目的：后续层不需要自己回溯之前锻模做了什么，减少因上下文遗忘导致的遗漏

### 不变

- L4 不做建构工作（那是 L3 的事）
- L4 不做质量判断（那是 L7.5/L7.6 的事）
- L4 不产交付物内容

## 修改2：L7.6 子agent审计层——打破自我验证循环

### 问题

当前验证链：L7.5 监天审计（主实例自审，按 vault 模板逐项判定）→ 自洽审计检查「L7.5 是否已执行」（同一实例检查自己，0 校验力）

需要引入一个在运行时与主实例隔离的验证者。

### 方案

在九层中插入新层 L7.6，位置在 L7.5 之后、L8 之前。

```
L7  注魂
  ↓
L7.5 监天审计（主实例按模板逐项判定，写入 forge_log）
  ↓
L7.6 子agent审计（独立第二方验证，写入 forge_log）  ← 新增
  ↓
L8  交付
```

### 执行流程

**触发条件**
- 重量档位：强制执行
- 中量档位：由判断器决定（任务复杂度高或涉及业务领域知识时触发）
- 轻量：不走

**审计材料**（主实例原文传递，不做摘要/倾向性转述）
- 锻造履历（forge_log 全部层记录）
- 监天审计记录（L7.5 产出的审计维度组、审计等级、问题清单）
- 最终交付物文本
- 用户核心诉求清单

**执行方式**
- 使用 task(subagent) 模式
- 工具限制：只读（read_file/grep 等），无写权限
- 不携带任何锻造上下文进入子agent

**审计指令**（三校验）
1. **监天审计完整性** — 监天的审计维度组是否匹配成果类型？审计等级是否合理？问题清单是否覆盖可识别的问题？
2. **交付物交叉检查** — 监天发现的问题，在交付物中是否已被修正？（监天判「条件通过」但问题未修→子agent 降级）
3. **整体质量终检** — 独立于监天，第三方视角看交付物是否有监天没发现的重大问题

**产出格式**
```
审计等级: 通过 / 不通过
对监天评价: 认同 / 部分异议（列出异议点）/ 不认同
补充问题: []（按严重程度排序）
建议: 放行 / 退回锻模
```

**处理规则**
- 子agent 判「不通过」→ 主实例阻断交付，退回 L3 锻模修正阻断级问题
- 子agent 判「通过」→ 进入 L8 交付
- 主实例可覆写子agent 结论，但须在锻造履历中记录覆写理由
- 子agent 审计记录写入 forge_log 的 L7.6 层

### 信任链设计

三环验证，每环有实质校验力：

```
L7.5 监天（主实例自身，快速模板化审计）
  → L7.6 子agent（同一系统另一实例，深度第二方验证）
    → 外部实例（独立对话/工具读 vault 履历做交叉核验，天衍不主动触发但接口开放）
```

前两环是框架内置的，第三环由用户或审核者自行决定是否执行。

### L7.6 与 L7.5 的分工

| | L7.5 监天 | L7.6 子agent |
|---|---|---|
| 执行者 | 主实例自身 | 独立子agent |
| 审计对象 | 交付物质量 | 监天审计质量 + 交付物终检 |
| 审计方式 | 按 vault 模板逐项判定 | 交叉核验、整体判断 |
| 阻断力 | 不通过→退锻模 | 不通过→退锻模 |
| 记录 | forge_log L7.5_监天 | forge_log L7.6_子agent审计 |

L7.5 和 L7.6 的阻断力叠加，但不是冗余——监天可能漏，子agent 可能偏，两层交叉才有实质校验力。

## 修改3：自洽审计 jian_tian_audit tier 重写

### 问题

当前 tier 定义：
```
验证 L7.5 监天审计是否已正确执行 → 检查 L7.5 是否已执行 → 确认 forge_log 包含 L7.5 记录
```

这是主实例检查自己——同一个 AI 执行了 L7.5，然后在自洽审计中检查自己留下了记录没有。永远通过。

### 方案

jian_tian_audit tier 从「检查 L7.5 是否已执行」改为「检查 L7.6 子agent 审计是否已执行且结论可用」：

```
<tier name="jian_tian_audit" priority="2">
  <positioning>第二方审计验证——质量级防御。验证 L7.6 子agent 审计是否已执行且结论可用</positioning>
  <flow>
    <step>检查 L7.6 是否已执行：确认 forge_log 中已包含 L7.6_子agent审计 层记录</step>
    <step>若 L7.6 状态为「skipped」（触发条件不满足的正常跳过）→ 视为正常，放行</step>
    <step>若 L7.6 状态为「executed」且审计等级为「通过」→ 放行至 L8</step>
    <step>若 L7.6 状态为「executed」且审计等级为「不通过」→ 阻断交付，退回 L3 锻模</step>
    <step>若主实例覆写了子agent 结论，检查覆写理由是否已在锻造履历中记录</step>
  </flow>
</tier>
```

这不是自我验证——主实例在检查一个独立实例的输出。校验力来源是子agent 与主实例的独立性，不是检查动作本身。

### 关联改动：item 0 更新

自洽审计 checklisit item 0 从「监天自适应审计执行」更新为「子agent 审计执行状态」：

```
<item id="0" name="子agent 审计执行状态" applies_to="medium|heavy">
  <check>确认 L7.6 已执行或已跳过且有记录。若已执行，读取审计等级。</check>
  <pass>L7.6 状态为 executed 且等级通过，或状态为 skipped 且有原因标注。</pass>
  <fail>L7.6 状态为 executed 但等级不通过 → 阻断；L7.6 在 forge_log 中不存在 → 补执行。</fail>
</item>
```

## 关联改动

### 1. 锻造履历格式更新

流程证据/_目录规范.md 中的逐层记录表需要新增 L7.6 行，插入在 L7.5 和 L8 之间：

```
| L7.5 监天 | executed | — | 审计维度组、审计等级、问题清单 |
| L7.6 子agent审计 | executed/skipped | 原因 | 审计等级、对监天评价、补充问题清单 |
| L8 交付 | executed | — | 交付物标识、复杂度档位 |
```

### 2. 监天-审计染色体层.md 兼容性

该文档描述的是监天（独立 AI）的审计维度体系，与 v0.12 中 L7.5 和 L7.6 的关系无冲突。L7.5 是主实例按监天的维度模板执行审计，L7.6 是子agent 的第二方验证——监天的维度体系仍然作为 L7.5 的审计骨架使用。

## 预期效果

| # | 改动 | 之前 | 之后 |
|---|------|------|------|
| 1 | L4 闭环 | 仅检查待证道列表归零 | 收敛检测+死锁中断+进度通信，能诊断循环健康度 |
