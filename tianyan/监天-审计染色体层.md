# 监天 —— 天衍审计染色体层

> 与泊言同级的天衍衍生子成果。泊言为天衍注入姿态，监天为天衍注入自审。
> 已落地：监天 v2.0.0，审计维度模板 6 份。
> 监天作为独立审计 AI 运行，天衍在交付前调用它完成审计+注入。

---

## 定位

```
锻模 → 兑冲 → 对齐 → 注魂（泊言：姿态）→ 监天（审计 + 注入）→ 交付
```

泊言回答的是"这像不像天衍该产出的东西"——魂归架构。
监天回答的是"这东西真的能用吗"——质量自证。

两者同级，互不统属。监天是独立 AI，天衍在交付前调它完成审计和染色体注入。

## 挂载方式（天衍调用监天）

天衍框架在锻造引擎的 L7（注魂）完成之后、L8（交付）之前，执行以下步骤：

```
L7 注魂完成
  │
  ▼
L7.5 监天审计 + 注入
  │
  ├─ ① 天衍传入：交付物文本 + 成果类型标签 + 本轮用户诉求清单
  │
  ├─ ② 监天执行审计
  │   ├─ 根据成果类型映射维度组
  │   ├─ 读取 vault 模板（领域/审计-{类型}.md）中的详细判定方法
  │   ├─ 执行审计判定
  │   └─ 输出审计报告
  │
  ├─ ③ 审计等级裁决
  │   ├─ "不通过" → 阻断交付，退回锻模修正阻断级问题
  │   ├─ "带条件通过" → 标记已知问题，放行至 L8
  │   └─ "通过" → 放行至 L8
  │
  ├─ ④ 染色体注入（仅在"通过"或"带条件通过"时执行）
  │   ├─ 将审计维度组转化为交付物内部的 <audit> 模块
  │   └─ 包含：触发条件、判定方法、修正指引
  │
  └─ ⑤ 审计记录
      ├─ 新维度 → 写入领域/审计-积累.md
      └─ 本次审计摘要 → 写入反馈/监天/审计日志.md（可选）
  │
  ▼
L8 交付
```

调用方式：天衍以独立提示词调用监天逻辑，将交付物文本 + 成果类型标签传入，监天返回完整的审计报告和注入物。

## 监天与 self_consistency_audit 的分工

| 层级 | 执行者 | 检查项 | 频率 | 阻断力 |
|------|--------|-------|------|--------|
| 流程级防御 | self_consistency_audit（黄金3条） | 路由匹配、排版合规、机器式表达 | 每次写入/修改前 | 阻断 |
| 流程级检查 | self_consistency_audit（独有条） | 单轮问题数、用户认知状态、复杂度档位、诉求覆盖、知识库回写、vault写入审计、认知边界自检 | 正式交付前 | 阻断 |
| 质量级防御 | 监天 | 结构完整性、逻辑闭环、冲突检测、指令密度、AI味检测、Agent/Skill规格、角色自洽、异常处理等深度审计维度 | 正式交付前 | 阻断/警告/建议 |
| 运行时自审 | 注入的 `<audit>` 模块 | 交付物自己的审计维度，每次核心动作后自动触发 | 运行时 | 阻断/日志 |

## 染色体注入机制

监天在交付前执行染色体注入——将审计维度以 `<audit>` 模块的形式植入交付物内部，使交付物获得运行时自审能力。

### 注入格式

被注入的 `<audit>` 模块结构：

```xml
<audit>
  <origin>监天 v2.0.0</origin>
  <injected_at>{时间戳}</injected_at>
  <dimensions>
    <item id="GA01" name="结构完整性" severity="阻断">
      <trigger>每次执行核心动作后自动触发</trigger>
      <check>identity 是否包含 name、self_conception、core_promise 三个必要字段？</check>
      <fix>定位缺失字段，补全对应内容</fix>
    </item>
    <!-- ... 每个维度一个 item -->
  </dimensions>
  <limitation>
    <item>监天不做运行时审计，仅做静态文本分析</item>
    <item>超出上下文窗口的内容未被审计</item>
  </limitation>
</audit>
```

### 注入后行为

- 交付物每次执行核心动作后自动触发 `<audit>` 自审
- 阻断级问题 → 阻断当前动作，返回修正方向
- 警告级问题 → 记录日志或提示用户
- 建议级问题 → 仅记录
- 连续两次阻断 → 熔断触发，进入严格模式，要求用户显式确认放行

## 监天质量闭环

监天的审计结果不是最终裁决：

1. **用户否决**：用户有权否决监天的单项审计结论。否决的维度记录到排除列表，对应类型下不再触发。
2. **误判积累**：用户明确指出监天误判，记录到 `反馈/监天/误判积累.md`。
3. **误判率降级**：误判率（用户明确误判次数 / 总审计次数）> 10% → 监天自动降级为"建议模式"，审计结果仅供参考，不阻断交付。
4. **进化**：误判作为监天的进化燃料，在版本更新中针对性修复。
