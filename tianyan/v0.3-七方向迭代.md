# v0.3 — 天衍框架七方向迭代

## 变更清单

### 1. 版本元信息嵌入 XML 本体
- XML 根层级新增 `<version_info>` 段，包含 version、previous_version、last_modified、changelog
- 每次迭代可在 XML 内直接追溯版本历史，不依赖 vault 外部分类

### 2. self_consistency_audit 自检清单工具化
- 19 条检查项升级为结构化 `<checklist>`，每条附 check/pass/fail 三段
- 新增第 20 项「认知边界自检」——防止将工具层表现误判为框架能力限制
- 新增 `<execution_protocol>` 定义触发时机和结果记录规则

### 3. 全路由价值提取
- 新增 `<polarity_extraction>` 段，独立于路由矩阵，定义所有路由的偏好提取规则
- 每条路由指定提取内容（如 Prompt-Instant 提取核心选择轴锚点、Skill-Forge 提取设计哲学锚点）
- 写入 `领域/路线-偏好积累.md`，写入前查重

### 4. auto_judgment 写入触发门槛下调
- 从「会遗憾」降至「有实质信息」
- 新增 4 类可积累信号：锚点偏好/风格偏好/偏差修正/项目事实

### 5. 奖赏制度机制设计
- 新增 `<reward_system>` 段，定义 4 类反馈信号（风格肯定/风格纠正/路由偏好/结构偏好）
- 写入 `反馈/天衍/偏好.md`，同类型信号叠加计数不重复追加
- 新对话加载时读取该偏好文件作为行为校准

### 6. 锻造流程中量级精简路径修正
- 新增 `<flexible_execution>` 段，定义中量级任务的三阶段合并路径（预检→构建→收口）
- 不挂 todo_write/complete_step 循环，内部逻辑完整对外不分步
- 需求中途转向时回退至完整九层

### 7. MCP 归档切换（协议层）
- `<obsidian_interface>` 新增 `<write_channel>` 段，定义 MCP Obsidian API 优先、文件系统 fallback 的双通道写入策略
- MCP 不可用时静默降级，不阻塞交付

### 8. 需求碰撞替代方向选择
- `expansion_protocol`：去掉"让用户从联想方向中选择或否定"，改为"碎片级灵感点独立抛出，自然收敛"
- `spectrum_positioning`：去掉"衍生两个方案供选择"，改为"抛关注点，定位从回应模式中收敛"
- `action_on_sparse`：去掉"收口确认"，改为"不收口，不抛确认问题，让用户自然回应"
- 三处改动统一逻辑：**不给选项让用户选，给灵感让用户碰**


### 9. auto_judgment 绑定硬锚点
- 从"想起来才查"改为绑定到 `self_consistency_audit` 的 `execution_protocol`——运行自检前必须先过 auto_judgment
- 不确定归属的笔记写入 `inbox/`
- 未检查直接交付视为自检失分

### 10. new_session_init 增加 vault 检索
- 新对话启动时用 `search_simple` 搜索关联笔记
- 读取 `反馈/天衍/偏好.md` 校准行为风格

### 11. vault 结构优化
- 新增 `inbox/` 暂存区（放下就走，定期清理）
- `领域/reasonix环境经验.md` — 对话知识沉淀
- `反馈/天衍/偏好.md` — 首次写入偏好记录


### 12. 路由矩阵全面重写

**旧：** 7条路由，含4条Agent相关、1条Skill、1条Task、1条Instant、1条Audit、1条兜底

**新：** 10条路由，按文字产出形态分类：

| 路由 | 说明 |
|---|---|
| Audit-Report | 审查诊断 |
| Agent-Definition | 智能体配置（forge/deliver/overwrite三子模式） |
| Skill-Definition | 能力模块 |
| System-Prompt | 角色定义（新增） |
| Task-Prompt | 任务指令 |
| Schema-Definition | 结构定义（新增） |
| Eval-Rubric | 评估标准（新增） |
| Knowledge-Artifact | 知识载体（新增） |
| Instant-Prompt | 即用文本 |
| Natural-Flow | 兜底 |

- core_essence 从"全谱系AI指令架构师"改为"一切文字驱动AI形态的架构师"
- capability_scope 明确：天衍只产文字，不产运行时，不挂工具，不依赖平台
- 知识库剔除商业计划书类型模板
