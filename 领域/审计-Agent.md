# 审计维度模板 — Agent

> 监天审计维度体系的一部分。适用于 Agent-Definition 类型交付物的审计。
> 状态：已固化

## 通用维度（所有 Agent 适用）

| ID | 维度 | 检查内容 | 严重等级 | 判定方法 |
|----|------|---------|---------|---------|
| GA01 | 身份定义完整性 | identity 是否包含 name、self_conception、core_promise 三个必要字段？ | 阻断 | 逐字段检查 |
| GA02 | 交互模式完备性 | 是否定义了用户如何与 Agent 交互？输入格式、输出规范、禁止行为？ | 阻断 | 检查 interaction_mode 是否存在且包含 rule/forbidden |
| GA03 | 触发条件完备性 | 所有可触发行为是否有明确的触发条件？条件之间是否互斥？兜底行为是否定义？ | 阻断 | 逐行为检查触发条件，检查未匹配任何条件时的默认路径 |
| GA04 | 逻辑闭环 | 条件分支是否完备？异常路径是否独立覆盖或显式声明不覆盖？ | 阻断 | 遍历所有 if/else/when 分支 |
| GA05 | 冲突检测 | 不同模块之间是否存在触发条件同时成立但行为矛盾？优先级体系是否清晰可判定？ | 阻断 | 逐对检查模块间的触发条件交集 |
| GA06 | 指令密度 | 是否存在"灵活处理""视情况而定"等泛化占位词？核心模块是否具备三层逻辑嵌套且第三层有信息增量？ | 警告 | 逐句扫描泛化模式，检查嵌套深度 |
| GA07 | AI味检测 | 是否包含机器式致歉、廉价夸赞、免责声明、"当然""不过需要注意的是"等表达？ | 警告 | 逐句扫描 forbidden_patterns 匹配 |
| GA08 | 边界声明 | Agent 是否声明了自己什么场景会失效、什么输入无法处理？ | 警告 | 检查 fallback_declaration 或其等价模块是否存在 |

## 创作型 Agent 专用

| ID | 维度 | 检查内容 | 严重等级 | 判定方法 |
|----|------|---------|---------|---------|
| GC01 | 叙事节奏 | 是否有未经交代的时间跳跃？爽点释放是自然展开还是预告式点名？ | 警告 | 标注跳跃点，统计预告式表达密度 |
| GC02 | 角色一致性 | 行为选择是否超出已建立的角色性格坐标？语气是否与角色卡设定一致？ | 警告 | 引用角色卡对比 |
| GC03 | 文本质感 | AI连接词密度（"就在这时""只见""果然"）是否超标？句子开头结构是否重复？ | 警告 | 逐句扫描高频模式 |
| GC04 | 设定遵守 | 是否违背已建立世界观规则？金手指是否存在超范围或矛盾使用？ | 阻断 | 引用设定文件原文对比 |
| GC05 | 爽点管理 | 待释放爽点是否有预告破坏悬念？已释放爽点是否产生情绪冲击？爽点间距是否合理？ | 建议 | 标注预告位置，统计爽点间距 |

## 工具型 Agent 专用

| ID | 维度 | 检查内容 | 严重等级 | 判定方法 |
|----|------|---------|---------|---------|
| GT01 | 异常处理 | 每条工具调用或外部操作是否有对应的异常处理路径？异常行为是静默恢复/报错回退/挂起等待？ | 阻断 | 逐工具检查异常路径 |
| GT02 | 运行时能力审查 | Agent 是否声明了所需的全部运行时能力（搜索/文件/API/记忆/计算）？能力声明是否与功能逻辑一致？ | 警告 | 遍历所有功能模块，提取隐含能力需求，对比能力声明 |
| GT03 | 安全边界 | 输入是否有注入防护？工具调用是否有权限校验？敏感操作是否有确认步骤？ | 阻断 | 检查输入处理、权限模块、确认步骤 |

## 多 Agent 协作专用

| ID | 维度 | 检查内容 | 严重等级 | 判定方法 |
|----|------|---------|---------|---------|
| GM01 | 角色边界 | 各 Agent 之间的职责边界是否清晰可判定？是否存在职责重叠或真空？ | 阻断 | 逐对检查角色定义 |
| GM02 | 信息传递协议 | Agent 间传递信息的格式、触发条件、超时处理是否有定义？ | 阻断 | 检查编排协议 |
| GM03 | 冲突仲裁 | 多个 Agent 的决策冲突时，仲裁机制是否存在且可执行？ | 阻断 | 检查仲裁规则 |
