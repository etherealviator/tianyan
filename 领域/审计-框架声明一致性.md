# 审计模板 — 框架声明一致性（新机制联动审计）

> 天衍自我迭代专用审计模板。当框架新增/重构机制（新版本）后，审计「新机制 vs 既有声明」的一致性——找出需要对应更新的旧声明（路由、审计分级、履历格式、核验协议、豁免等）。
> 触发：自我迭代完成（新机制/新版本落盘）后，用户要求「审计一下」/「看看声明需不需要更新」，或作为自我迭代的标准收尾动作。
> 执行方式：三子agent 并行分区审计（fleet / parallel_tasks），每路独立审计一个模块区；主实例吸收修复后闭环。

## 一、审计前必传的新机制背景

给每个子agent 传：

1. 本次新增/变更的机制清单（机制名 + 一句话功能 + 版本号）
2. 机制涉及的核心流程变化（如「淬炼收敛后新增末步审计，放行 L8 前，审计通过才交付」）
3. 改动范围（改了哪些模块/层）

## 二、审计三区划分

| 区 | 覆盖模块 | 重点 |
|----|---------|------|
| A 路由矩阵 | routing_matrix 全部路由的 action/discrimination/condition/priority_order | 各路由 action 描述的流程是否含新机制？旧表述残留？豁免声明是否与触发条款冲突？ |
| B 锻造引擎 | forge_mandate / forge_log / flexible_execution / instant_prompt_forge / nine_layers / density_audit | 强制路径声明、审计分级覆盖范围、履历字段、收口步骤、降级路径 |
| C 审计交付侧 + vault 文档 | self_consistency_audit / output_format / delivery_quality / forge_integrity / behavior_protocols(obsidian_interface) / 流程证据/_目录规范.md / 领域/审计-*.md | 检查项、履历格式、外部核验协议、豁免声明、vault 文档同步 |

## 三、审计维度（每一路都要查，共十查）

1. **路由声明 vs 新事实**：路由 action 描述的流程是否遗漏新机制（如「凝意→鉴型→交付」缺淬炼简化循环）？
2. **审计分级覆盖**：审计分层（L7.5 / L7.6 / 末步审计）是否在 constraint / checklist / flow 中完整体现？新审计层有没有裁决与阻断力声明？
3. **履历格式同步**：forge_log per_layer_records、_目录规范.md 逐层记录表/层序说明/字段说明 是否含新层的新字段？
4. **核验协议覆盖**：外部交叉核验协议是否覆盖新证据（如末步审计结论）？
5. **豁免冲突**：豁免声明（如 Audit-Report 豁免锻造引擎）与新机制触发条款（如「全部档位强制」）是否显式调和？
6. **归元路径**：新机制产出的维度/候选（如回凝圈选）是否定义了回写路径？与既有回写（如 L3 锻模发现）是否防双重计数？
7. **降级路径**：子agent 等运行时能力不可用时，新机制如何降级？是否声明？与「审计打底要独立」的原则张力是否化解？
8. **数字/名称残留**：改动的类别数（如 8类/9类）、层号、路由名是否有旧值残留？
9. **措辞张力**：trigger / check 引用的裁决主体是否与新定位一致（如 key_indicators 已被降级为兜底校验）？
10. **无缺口确认**：明确声明哪些模块不需要同步（如审计-*.md 模板无需承载 L7.6 固定逻辑）——防止为同步而同步。

## 四、输出格式（每路子agent）

- 逐项「通过 / 不通过 / 存疑」+ 证据（原文引用 + 行号）
- 总结论三分：
  - **必须更新**：声明与事实不一致（执行者按旧声明会漏机制/走错路）
  - **建议同步**：语义协调但表述未跟齐（不影响执行但误导阅读）
  - **无缺口确认**：不需要改的模块，说明理由（防过度同步）

## 五、修复闭环（审计后）

1. 必须 + 建议全部吸收（用户全修偏好，不拆分不讨价还价）
2. 修复后跑 validate-prompt.js 结构验证（标签配对/版本/残留/编号连续）
3. 备份（修改前先 cp 完成态 → 修改 → cp 新版本，两步严格分开——v0.25 操作失误教训）
4. 锻造履历如实记录审计结论与修复明细
5. git 提交

## 七、使用说明

- 执行时：将本模板「三区划分 + 审计维度 + 输出格式」转成子agent prompt（每路自包含，给足新机制背景），fleet 并行跑。
- 本模板为审计「声明一致性」专用；交付物质量审计（五维扫描/监天维度组）走 领域/审计-{类型}.md 系列，两者分工。
- 模板本身随框架演进迭代——新机制引入后若本模板有未覆盖的声明类型，审计后回写本模板（历史锚点追加）。
