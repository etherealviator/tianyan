## 已记录的维度

### 1. 诚实路线 vs 指纹路线
**描述：** 去AI味/文风控制存在两条路线。指纹路线（提取作品风格特征→结构化参数→注入生成）已被实证证伪——用户以完整资产库（江南五版原文+文风提取+人物卡+框架）喂给AI续写龙族，产出仍为"一坨屎"。诚实路线（不清除文风、只清除AI味，目标从"像谁"降为"不像机器"）是可达路径。
**触发场景：** 任何涉及文风复刻/风格迁移/续写的Skill或Agent设计。
**触发计数：** 1
**否定计数：** 0
**最近触发：** 2026-08-04

### 2. 灵魂审计六条
**描述：** 叙事文本"神"的可操作化检查清单。①细节来源测试（删掉有损失=长出来的/无损失=摆上去的道具）②幽默归属测试（人物自己的刺 vs 作者插话）③呈现/告诉测试（第三人称叙事中情绪直告=AI味重灾区）④灵魂在场测试（去掉人物名还认得出吗）⑤闲笔测试（全无闲笔=机器感）⑥赌注测试（全是安全选择=最安全的模仿=没有灵魂）。校准基准：江南原文 vs AI续写实证对比。
**触发场景：** 叙事类文本的质量审计/续写评估。
**触发计数：** 1
**否定计数：** 0
**最近触发：** 2026-08-04

### 3. 硬指纹五层
**描述：** AI味机械指纹库，分词汇层（套话连接词/空洞升华词/抽象空洞修饰）、句式层（三段式/否定式排比/虚假范围/破折号揭示/系动词回避）、结构层（引言-三点-总结/每段功能化/结尾必升华）、情感层（情绪直告/总结性抒情/排比抒情）、修辞层（道具式细节/空洞比喻/金句欲）。可机械识别，命中即处理。
**触发场景：** 任何需要快速清除AI味的文本处理。
**触发计数：** 1
**否定计数：** 0
**最近触发：** 2026-08-04

### 4. 去AI味≠人味表演
**描述：** 风格护栏：禁止"为了像人而人味"——刻意口语、刻意瑕疵、刻意自嘲、刻意断句。人味的唯一来源是诚实——写真实会写的，删真实不会写的。判断标准：敏感读者读完不觉得"表演痕迹重"。
**触发场景：** 去AI味处理后的人味注入环节。
**触发计数：** 1
**否定计数：** 0
**最近触发：** 2026-08-04

### 5. 四铁律优先级
**描述：** 信息密度铁律 > 原意铁律 > 人物一致性铁律 > 诚实铁律。任何风格化处理不得越过。目标优先（AI味完全清除）、诚实兜底（无法自然清除处如实标注不硬改），两者冲突时诚实优先于"看起来干净"。
**触发场景：** 文本改写/润色类Skill的约束设计。
**触发计数：** 1
**否定计数：** 0
**最近触发：** 2026-08-04

### 6. 龙族人物性格基准表
**描述：** 路明非（贱怂自嘲+关键时刻善良，对最亲的人也嘴硬）、楚子航（冷寡言行动派，情绪藏动作里）、芬格尔（贱话痨捞便宜，底线是路明非）、恺撒（自恋话痨骄傲，浮夸但真诚）、路鸣泽（正经与孩子气交替，说真话时最轻描淡写）。单点维护，供续写/审计引用。
**触发场景：** 龙族续写或涉及龙族人物的任何创作任务。
**触发计数：** 1
**否定计数：** 0

## 待验证假设

- 灵魂审计六条对非龙族叙事文本（其他作者/原创）的适用性：理论上通用（判定标准不绑定龙族），待实证。
- 硬指纹库的时效性：AI味指纹随模型迭代漂移，需定期对照新模型输出校准。

### 7. 隐晦AI味（二级AI味，过度矫正产物）
**描述：** 去AI味执行过度产生的二级AI味，比一级AI味（排比/升华/套话）更隐蔽、更难闻。五类：①克制留白（短句+戛然而止冒充余韵，如"世界安静了"）②编造细节（凭空编"有来历的物件"伪装人味，无根细节比抽象更假）③强行闲笔（植入感明显的闲笔）④刻意自嘲（为展示人物嘴硬而安排自嘲台词）⑤短句装深沉（句长变化服务于"显得会写"而非内容节奏）。
**触发场景：** 任何"去AI味/人味化"处理——执行者极易在"去掉A味"的压力下滑向"装深沉"（最安全的选择），需显式防范。
**触发计数：** 1
**否定计数：** 0
**最近触发：** 2026-08-04（用户批注：一没有衔接感依旧ai克制留白；三傻逼；四安静了然后呢？克制感溢出屏幕了）
**关键教训：** 用户在演示验证时指出"去AI味不能执行成另一种表演"——目标从"去掉A味"应是"把事写好"，而非"换一种不像AI的写法"。高燃直接燃，酣畅淋漓写战斗本身，不安排"人性的细节"做铺垫；该给结果给结果。

### 8. 代词密度/承前省略
**描述：** AI 结构性毛病——默认显式主语，导致人称代词（他/她/它）高频重复（连续3句以上同一代词开头）。中文的合法语感是承前省略：连续动作共主语只出现一次，后续零主语连动；另可物作主语（刀/血/爪替代"他"当句首）、角色称呼替代（持剑者/路明非）、无主句（"来不及收刀"）。参照：江南"利爪→持剑者→铁剑→利爪"主语轮换。搜索佐证：现代汉语复句研究（承前省略主语为合法语篇手段）、语篇衔接理论（避免重复而替换成分）。
**触发场景：** 任何叙事文本的语感检查——动作密集段落是重灾区。
**触发计数：** 1
**否定计数：** 0
**最近触发：** 2026-08-04（用户批注："他他他，你他个屁啊，人家诗句都忌讳重字"）
**关键教训：** 诗歌忌重字，散文同样忌高频代词。修正后示范文本"他"密度从12次/段降至近0，靠承前省略+物作主语，语感立变。

### 9. 创作执行端能力边界（转型决策）
**描述：** 叙事创作的"执行端"超出当前模型能力边界。实证链：①指纹路线（文风提取→注入）证伪（AI续写龙族一坨屎）②灵魂审计六条能识别问题但修正执行连续翻车（克制留白/编造细节/强行闲笔/代词密度，用户逐句批回）③结论：识别的判断力模型有，创作生成能力没有。skill 无法弥补——任何规则都无法让模型"写出灵魂"，只能让模型"识别并清除机械痕迹"。
**决策：** no-ai-flavor v2 转型为非创作类文本润色与审计（论述/分析/报告/公文/技术文档/邮件）。非创作类的"好"有客观标准（信息准确/逻辑连贯/表达直接），不需要创作天赋，模型可覆盖。
**触发场景：** 任何写作/续写类 skill 或 Agent 的设计——先问"这个任务的执行端是创作还是信息组织"。创作→设能力边界预期，只做识别/审计；信息组织→可全量执行。
**触发计数：** 1
**否定计数：** 0
**最近触发：** 2026-08-04（用户决策："写作目前的模型都是灾难级，只能等专门训练的或者agi了，这个skill就专门转型成非写作类文本润色与审计"）
**待验证：** 模型能力升级（新模型/专门训练）后，创作执行端边界是否移动——届时可考虑 v3 恢复叙事模式。

### 10. 压缩度控制（文体要素保护）
**描述：** v2.0 暴露的执行缺陷——把"直接"执行成"压缩"，把报告削成骨架。根因：结构审计和 P3 无压缩度上限，信息密度最大化成了唯一目标，论证展开、背景交代、目的陈述等文体要素被误删。修正：genre 参数增加压缩度语义（报告-作业/学术=保留论证展开；报告-决策=可骨架化；邮件/公文/技术文档各自校准），新增 genre_protection 文体要素保护清单（要素承载信息或承担文体功能→保留；万金油填充→清除），P3 修订为"直接≠压缩"。
**触发场景：** 任何带文体格式的文本处理（报告/公文/邮件）——"清AI味"与"保留文体"的边界判断。
**触发计数：** 1
**否定计数：** 0
**最近触发：** 2026-08-04（用户反馈："直接削成骨架了，虽然信息密度变高了，表达方式好了许多，但是用这个skill的话，混混学校报告之类的东西就不好混了"）
**关键教训：** AI味清除 ≠ 文本瘦身。学校报告/作业报告需要论证展开、段落完整、格式体面——那是文体要求不是AI味。skill 处理带文体的文本时，必须先问"这种文体不可删的要素是什么"，再动手。
